# Phase 43 — 페이지 도구 모음 재편 (2-2 · 2-3 · 2-4)

> 상태: **draft(예약·미착수)**
>
> 착수 전 stale 가드:
> ① [Phase 42 T1](phase_42.md)이 `flex-wrap`으로 응급 처치를 했는가(했으면 이 Phase는 근본 정리)
> ② 도구 모음 버튼이 아직 9개인가
> ③ `handleConvertToDatabase`를 부르는 자리가 아직 툴바 하나뿐인가
> ④ 템플릿 목록이 아직 "빈 페이지 ~ 독서 목록"인가

## 왜 이 일인가

**[Phase 42 T1](phase_42.md)이 고친 것은 증상이고, 원인은 여기다.**
버튼 9개를 768px에 넣으려 한 것 자체가 문제다. `flex-wrap`은 안 깨지게만 할 뿐
2~3줄로 늘어난 도구 모음은 글 쓰는 화면을 침범한다.

**사용자 요청 3개가 정확히 이 원인을 줄이는 방향이다:**

| 요청 | 효과 |
|---|---|
| 2-2 가져오기·내보내기를 모달 하나로 | 버튼 2개 → 1개 (인쇄·텍스트 복사도 흡수 → 4개 → 1개) |
| 2-3 데이터베이스로 전환을 오리·설정으로 이관 | 버튼 1개 제거 (가장 넓은 버튼, ~150px) |
| 2-4 템플릿을 실제 노션처럼 | 버튼 수와 무관하나 같은 화면 |

**결과: 9개 → 4개**(즐겨찾기 · 표지 · 버전 · 내보내기 · 웹에 공개 중 일부는 `⋯` 메뉴로).

## T1 — 내보내기·가져오기 통합 모달 (2-2)

### 지금 흩어져 있는 것

| 기능 | 지금 위치 | 상태 |
|---|---|---|
| 가져오기 (.md) | 툴바 `<label>` + 숨은 file input | 있음 |
| 인쇄 · PDF | 툴바 버튼 | 있음 (Phase 30 T4-a 지면 규칙) |
| 텍스트 복사 | 툴바 버튼 | 있음 |
| Markdown **내보내기** | `onExportReady`로 함수는 준비됨 | **버튼이 없다** |

**사용자 지적이 정확하다** — "가져오기 기능이 있으면 내보내기 기능도있어야하는데".
`toMarkdown` 함수가 [`PageEditor.tsx:292`](../../apps/web/src/components/PageEditor.tsx#L292)에
이미 준비돼 있는데 **부르는 자리가 없다.**

### 만들 것

**버튼 하나 → 모달.** 요청이 명시한 항목("인쇄 엑셀 클립보드 인쇄 마크다운 등등"):

| 탭 | 항목 | 구현 근거 |
|---|---|---|
| 내보내기 | Markdown (.md) | `toMarkdown` 이미 있음 |
| | 텍스트 (클립보드) | 이미 있음 |
| | 인쇄 · PDF | 이미 있음 (Phase 30 T4-a) |
| | **CSV/엑셀** | **[확인 필요]** — 표 블록이 있을 때만. 문서 전체를 CSV로 만드는 것은 의미가 없다 |
| | 템플릿(.template.json) | 이미 있음 (Phase 30 T3) |
| 가져오기 | Markdown 파일 | 이미 있음 (CP949·UTF-16 판별 포함) |
| | 템플릿 파일 | 이미 있음 |

- **기존 구현을 재사용한다. 하나도 다시 만들지 않는다.**
  이 Task의 대부분은 **배선**이고, 새로 만드는 것은 CSV/엑셉 하나뿐이다.
  재구현은 **CLAUDE.md 3-5절 최고 심각도 인벤토리 위반**이다.
- **"엑셀"의 뜻이 또 갈린다.** [PENDING 8번](../loop-eng/PENDING.md)이 이미 같은 질문을 남겼다
  (열 집계 vs A1 스프레드시트). 여기서는 **표 블록 → CSV**로 해석한다 —
  그게 "엑셀로 내보내기"의 최소 성립 형태다. **`.xlsx` 생성은 하지 않는다**(의존성이 필요하고,
  CSV를 엑셀이 그대로 연다).
- 접근성: 모달은 포커스 트랩 + Esc 닫기 + `role="dialog"` + `aria-labelledby`.
  **포커스를 모달 안으로 옮긴다** — [Phase 34](phase_34.md) 리뷰에서 찾은 빈틈과 같은 부류다.
- **표가 없는 문서에서 CSV 항목을 고를 수 있게 두지 않는다.** 고를 수 있게 두면 사용자는
  빈 파일을 받고 "왜 비었지"를 겪는다. [Phase 33](phase_33.md)이 집계 선택에서 쓴 판단과 같다 —
  **화면에서 답을 주는 대신 선택지에서 뺀다.**

## T2 — 데이터베이스로 전환 이관 (2-3)

### 원문

> "데이터베이스로 전환은 왜 필요한지 모르겟고 오리한테 시켜서 할수있거나 설정에서 전체 db화 하는식으로 해줘"

### 지금 상태

[`PageEditor.tsx:591`](../../apps/web/src/components/PageEditor.tsx#L591)의 버튼 하나가
`handleConvertToDatabase`를 부른다. **이 버튼이 표(데이터베이스) 기능의 유일한 입구다.**

### 하려는 것 — 지우지 않고 옮긴다

**지우면 표를 만들 길이 사라진다.** [`DatabaseView.tsx`](../../apps/web/src/components/DatabaseView.tsx)(638줄)와
[Phase 33](phase_33.md)의 열 집계가 전부 이 입구에 매달려 있다.

세 곳으로 옮긴다 — **요청이 명시한 두 곳 + 발견 가능성 하나**:

1. **오리에게 시켜서** — 오리 도구(`convertPageToDatabase`)를 추가한다.
   [Phase 30 T2](phase_30.md)가 만든 도구 체계를 그대로 쓴다.
   **되돌리기 어려운 변환이므로 승인 카드를 강제한다** — CLAUDE.md 5절 + Phase 30이 세운 계약.
   **[확인 필요] 이 변환이 되돌릴 수 있는가.** 되돌릴 수 없으면 승인 문구를 그에 맞게 강하게 쓴다.
2. **설정에서** — "새 페이지를 만들 때 기본으로 데이터베이스로" 옵션.
   요청의 "설정에서 전체 db화"를 이렇게 읽었다. **[해석 필요]** "이미 있는 페이지 전부를
   한꺼번에 DB로 바꾼다"는 뜻일 수도 있다 — 그건 **되돌릴 수 없는 일괄 변경**이라
   추측으로 만들지 않는다. 착수 시 확인한다.
3. **`⋯` 더보기 메뉴** — 툴바에서 빼지만 완전히 숨기지 않는다.
   기존 사용자가 쓰던 자리가 사라지면 "기능이 없어졌다"가 된다.

- 회귀 잠금: 변환 로직 자체는 **한 줄도 바꾸지 않는다.** 입구만 옮긴다.
  기존 표가 그대로 열리는지 테스트로 확인한다.

## T3 — 템플릿을 실제 노션처럼 (2-4)

### 원문

> "템플릿에대한 빈페이지 ~ 독서목록까지 있는데 이거 빈페이지말고 선택해서 나오면
> 실제 노션에서 사용중인 회의록처럼 보이도록해줘 (템플릿)"

### 지금 상태

[Phase 30 T3](phase_30.md) + `0ddcf12`로 템플릿 목록(빈 페이지·회의록·일기·포트폴리오·회고록·독서 목록)이 있다.

**[확인 필요 — 착수 전 반드시 볼 것] 각 템플릿의 실제 내용이 몇 줄인가.**
사용자가 "빈페이지말고"라고 쓴 것은 **템플릿을 골랐는데 거의 빈 화면이 나왔다는 뜻**으로 읽힌다.
그렇다면 문제는 목록이 아니라 **내용의 빈약함**이다.

### 만들 것

**"실제 노션에서 사용중인 회의록처럼"** — 노션 템플릿이 빈 문서와 다른 점은 구조다:

- 제목 + 메타 블록(날짜 · 참석자 · 안건) — **표 또는 속성 형태**
- 섹션 제목(h2)이 미리 놓여 있음: 안건 / 논의 / 결정 사항 / 액션 아이템
- 액션 아이템은 **체크박스 목록**이고 담당자·기한 자리가 있음
- 안내 문구(placeholder)가 각 섹션에 있어 **뭘 써야 할지 알려준다**

이걸 6개 템플릿 전부에 적용한다.

- **[Phase 34](phase_34.md)와의 계약을 지킨다**: 발표 모드가 **h1을 장 경계로** 삼는다.
  회의록 템플릿에 h1을 여러 개 넣으면 **회의록 하나가 여러 장으로 흩어진다.**
  Phase 34가 "h2로는 나누지 않는다"고 정한 이유가 정확히 이것이다
  ("나누면 회의록 템플릿(h2가 5개)이 5장으로 흩어진다").
  **→ 템플릿 안의 섹션 제목은 h2 이하만 쓴다. 이걸 테스트로 잠근다.**
- 템플릿 정의는 **core에 데이터로** 둔다(지금 구조 유지). 컴포넌트에 하드코딩하면
  Phase 30 T3의 "템플릿으로 저장 → .template.json" 경로와 형식이 갈라진다.
- **블록 타입 허용 목록을 지킨다** — Phase 30 T3이 외부 템플릿 파일에 대해 세운 방어다.
  우리 내장 템플릿이 그 목록 밖 블록을 쓰면 **내보냈다 가져올 때 깨진다.**

## 의존 계약

- **신규 의존성 0개.** CSV는 문자열 조립이면 된다(`.xlsx`를 만들지 않는 이유).
  모달은 기존 `ConfirmDialog` 패턴을 참고하되 **다목적 모달이라 별 컴포넌트로 만든다.**
- **마이그레이션 0개.** T2-2의 "기본을 DB로" 옵션은 **[Phase 49](phase_49.md)의 설정 저장 경로**를
  쓴다. 그게 마이그레이션 대기 중이므로 **이 Phase에서는 로컬 설정으로 두고 Phase 49에서 승격**한다.
- **`PageEditor.tsx`가 1121줄이다.** 이 Phase가 툴바를 재편하므로 **툴바를 별 컴포넌트로 분리**한다
  (`PageToolbar.tsx`). 파일이 커지는 것은 "너무 많은 일을 한다"는 신호이고,
  이 Phase가 정확히 그 부분을 건드린다 — **요청 범위 안의 정리다.**

## 하지 않을 것

- **`.xlsx` 생성 라이브러리 도입.** CSV로 충분하고 엑셀이 그대로 연다.
  [Phase 34](phase_34.md)가 `pptxgenjs`를 거부한 것과 같은 판단.
- **데이터베이스 전환 로직 재작성.** 입구만 옮긴다.
- **"전체 db화"를 일괄 변환으로 해석해서 만드는 것.** 되돌릴 수 없다. 확인 후에.
- **템플릿에 h1 여러 개 넣기.** Phase 34의 발표 모드가 깨진다.
