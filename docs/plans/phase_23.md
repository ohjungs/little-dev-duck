## 설계 결정 (ponytail 7단계)

- **모델이 반복 문법을 지어내게 두지 않는다.** 받은 문자열을 그대로 저장하면 `FREQ=BIWEEKLY`
  같은 없는 규칙이 DB에 들어간다. **core `parseRecurrence`로 검증**해 통과한 것만 저장하고,
  실패하면 조용히 버리지 말고 오류로 되돌린다(사용자는 반복이 걸린 줄 안다).
- **날짜도 마찬가지로 엄격히 본다.** `YYYY-MM-DD`만 받는다. 모델이 타임스탬프를 만들면
  시각·타임존을 지어내고, 그건 피드백 iter5에서 실제로 터진 버그다(일정이 11일 뒤에 생성됨).
- **저장 시각 규약을 지킨다 — `T00:00:00.000Z`(UTC 자정).**
  할 일 화면은 오늘 필터를 `dueDate.slice(0, 10) === todayIso()`로 판정한다(문자열 앞 10자리).
  KST 자정으로 저장하면 UTC로는 전날 15:00이라 **잘라낸 날짜가 하루 앞선다.** 지금까지
  마감일을 쓰는 곳이 없어 드러나지 않았을 뿐이고, 오리가 첫 기록자가 되므로 여기서 규약을
  못박고 테스트로 잠근다.
- **승인 카드에 마감일·반복을 보여준다.** 승인 게이트의 취지는 "무엇을 승인하는지 정확히
  아는 것"이다(CLAUDE.md 5절). 모델이 날짜를 잘못 잡았을 때 사용자가 승인 전에 알아채야 한다.
  반복은 `describeRecurrence`로 한국어로 풀어 보여준다 — `FREQ=WEEKLY;BYDAY=TU`를 그대로
  띄우면 판단에 도움이 안 된다.

## Task

### T1 createTodo 도구에 마감일·반복 (api, STDD)
- **수용 기준**:
  - 도구가 `dueDate`(선택, `YYYY-MM-DD`)와 `recurrence`(선택, RRULE 부분집합)를 받는다.
  - 형식이 어긋나면 **저장하지 않고 오류를 돌려준다**(조용한 무시 금지).
  - 달력에 없는 날짜(2026-02-30 등)를 거부한다.
  - 반복은 `parseRecurrence`를 통과한 것만 저장한다.
  - 마감일 없이 반복만 주면 그대로 둔다(반복 자체는 마감일 없이도 성립하고, 첫 완료 시
    `rolloverDueDate`가 오늘 기준으로 다음 회차를 잡는다).
  - 기존 호출(제목만)의 동작은 **한 글자도 바뀌지 않는다**.
- **의존 계약**: 기존 `createTodo`(Phase 20에서 recurrence 이미 받음). 새 마이그레이션 없음.

### T2 승인 카드에 노출 (web)
- **수용 기준**: 승인 카드에 마감일과 반복(한국어 요약)이 보인다. 없으면 줄이 뜨지 않는다.
