## 왜 이 Phase가 Phase 49에 붙는가

**설정은 흩어지면 안 된다.** [Phase 49 T1](phase_49.md)이 "내가 말한 모든 것을 설정에서"를
위해 카테고리 구조와 저장 경로를 만든다. **메신저 설정도 그 구조 안에 들어간다.**

**따로 만들면 설정 화면이 두 개가 된다** — 사용자 요청 6-1("내가말한 모든것들은 설정에서
제어가능해야하고")의 정반대다.

> **이 Phase의 원칙: 새 설정 화면을 만들지 않는다. Phase 49의 구조에 항목을 추가한다.**

## T1 — 알림 심화 (M 19항목)

**[Phase 51 T2](phase_51.md)가 만든 배선 위에 얹는다.** 그 배선은 [Phase 44 T1](phase_44.md)의
뽀모도로 알림과 **같은 권한·같은 API·같은 방해금지 판정**을 쓴다. 이 Phase도 같다.

| 항목 | 판단 |
|---|---|
| M-007 멘션만 알림 · M-008·M-009 키워드 알림 | **값이 크다.** 방이 늘면 전부 알림은 곧 전부 끔이 된다. 키워드 판정은 **결정적 — 코드로**(HD-003) |
| M-011 요일별 방해 금지 | `QuietHoursSetting`의 확장. **재구현 금지** |
| M-014·M-015 알림음 선택·방별 지정 | [Phase 44](phase_44.md)가 음원 자산을 정리한다 — 그걸 공유 |
| M-019 알림 그룹화 · M-020 요약 | **알림 폭주 대책이다.** 그룹방이 생기면(Phase 53) 필요해진다 |
| M-021 중요 알림 우선순위 | 판정 근거가 모호하다 — **멘션·키워드로 환원**하는 편이 정직하다 |
| M-025 이메일 알림 | **Supabase SMTP 발송 상한에 걸린다**([Phase 41 T3](phase_41.md)에서 조사한 그 한계). 그 숫자를 먼저 확인 |
| M-027 텔레그램·슬랙 릴레이 | 외부 서비스 = 확정 스택 밖. **아웃바운드 웹훅(S-024)으로 일반화**하는 편이 낫다 |
| M-028 히스토리 · M-029 스누즈 · M-031 테스트 발송 | 저비용 · 값 중간 |
| M-032 예약 발송 전 알림 · M-033 재알림 간격 | [Phase 54](phase_54.md)의 예약 전송에 딸린다 |
| M-034 알림 실패 로깅·재시도 | `action_log`에 담는다. **새 로그 테이블 금지** |
| M-016 진동 | 모바일 전용 → [Phase 60](phase_60.md) |
| M-018 잠금 화면 내용 숨김 | 모바일/OS 영역. 우리가 제어하는 부분만 |

- **알림 설정이 늘어날수록 "왜 알림이 안 왔지"가 늘어난다.**
  → **설정 화면에 "지금 이 방의 알림이 켜져 있는가"를 한 줄로 답하게 한다.**
  판정이 여러 겹(전체 · 방별 · 방해금지 · 집중모드 · 권한)이라 **사용자가 추적할 수 없다.**
  이 저장소 원칙: **정체 모를 실패 대신 왜 안 되는지 말한다.**

## T2 — 설정 항목 (T 17항목)

- 설정 화면 구조(T-001) · 글자 크기(T-004) · 말풍선 밀도(T-005) · 언어(T-006) ·
  알림 설정 진입(T-007) · 데이터 절약(T-009) · 자동 다운로드(T-010) · 미디어 자동 재생(T-011) ·
  링크 미리보기 자동 생성(T-012) · 백업·복원 메뉴(T-015) · 버전 정보(T-023) ·
  로그 수집 동의(T-026) · 진단 로그 내보내기(T-027) · **실험 기능 토글(T-028)** ·
  설정 검색(T-030) · 초기화(T-031) · 내보내기·가져오기(T-032).
- **T-028 실험 기능 토글(feature flag)** — 사용자 요청 6-1의 "기능추가설정"이 이것에 가깝다.
  [Phase 49](phase_49.md)의 `FEATURES` 12종 토글이 **이미 같은 구조다.**
  → **그 목록에 추가한다. 새 플래그 체계를 만들지 않는다.**
- **T-030 설정 검색** — [Phase 49 T1](phase_49.md)이 이미 "항목이 이만큼 늘면 찾을 수 없다"고
  적었다. **거기서 만들고 여기서는 메신저 항목이 검색되게만 한다.**
- **T-031 설정 초기화는 되돌릴 수 없다.** 확인 문구를 다르게 쓴다 —
  [Phase 35](phase_35.md)가 계정 삭제에서 세운 계약("손이 기억한 대로 눌러
  되돌릴 수 없는 쪽까지 지운다").
- **T-006 언어 설정은 [Phase 57](phase_57.md)의 i18n 구조(X-010)가 없으면 껍데기다.**
  → 순서를 지킨다. **토글만 만들어 두고 아무것도 안 바뀌면 그게 거짓말이다.**
- **T-009·T-010 데이터 절약은 무료 티어 대역폭(5GB/월) 대책이다.** 값이 실제로 있다.

## T3 — 방별 표시 설정 (E 3항목)

- 배경 테마(E-028) · 말풍선 스타일(E-029) · 글자 크기 방별(E-030).
- **[Phase 49](phase_49.md)의 강조색 선택(T-003)과 같은 부류다** —
  **검증된 팔레트로 제한한다.** 자유 색상 선택기를 주면 대비가 깨져 글자가 사라진다.
  Phase 49가 세운 그 판단을 그대로 쓴다.

## T4 — 멀티디바이스 알림 조율 (B 5항목)

- 기기별 읽음 위치 동기화(B-010) · **기기별 알림 억제(B-011)** · 기기 이름(B-012) ·
  PC 로그인 시 모바일 알림 중지(B-013) · 시계 스큐 보정(B-018).
- **B-011이 실제 불만의 원인이 될 항목이다** — 웹에서 읽었는데 데스크톱 알림이 또 뜨면 짜증난다.
  [Phase 51](phase_51.md)의 읽음 실시간 반영(J-013)이 있으면 **거의 따라온다.**
- **B-018 시계 스큐**는 [Phase 50](phase_50.md)이 이미 막았다 — `seq`를 **서버가 부여**한다.
  **여기서 다시 만들 것이 없다.** 확인하고 닫는다.

## 의존 계약

- **마이그레이션 1~2건**(방별 표시 설정 · 알림 설정 확장). down 포함.
  **[Phase 49](phase_49.md)의 설정 저장 경로를 쓴다** — 새 테이블을 만들지 않는다.
- **신규 의존성 0개.**

## 하지 않을 것

- **새 설정 화면.** 요청 6-1의 정반대다.
- **새 feature flag 체계.** `FEATURES` 12종이 이미 있다.
- **새 로그 테이블.** `action_log`가 있다.
- **`QuietHoursSetting`·`NotifySetting` 재구현.** 인벤토리 위반.
- **자유 색상 선택기.** 대비가 깨진다(Phase 49 판단).
- **아무것도 안 바꾸는 언어 토글.** i18n 없이 만들면 거짓말이다.
- **시계 스큐 보정 재구현.** Phase 50의 서버 `seq`가 이미 답이다.
