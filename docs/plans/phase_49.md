## T0 — 마이그레이션 일괄 적용 (사용자 실행)

```
supabase db push
```

**적용 뒤 한 번 더 — 관리자 지정 (6-2)**

사용자가 **두 이메일 모두 관리자**로 결정했다.

```sql
update public.profiles set role = 'admin'
where email in ('5555jungs@gmail.com', '555jungs@gmail.com');
```

- 역할 기본값이 `user`라 **적용 직후에는 관리자 화면의 사용자 관리가 안 보인다.**
- **[확인 필요] `555jungs@gmail.com`(5가 3개) 계정이 실제로 가입돼 있는가.**
  없으면 그 행은 0건 갱신되고 조용히 지나간다. **가입 후 다시 실행해야 한다** —
  이걸 적어 두지 않으면 "관리자 권한이 안 들어갔다"로 다시 올라온다.
- 롤백 스크립트는 `supabase/rollback/`에 `_down.sql`로 **전건 있다**(실측 확인).

## T1 — 설정 화면 재편 (6-1)

### 원문

> "내가말한 모든것들은 설정에서 제어가능해야하고 기능추가설정 이런것도 있으면좋곗고,
> 목록화해서 여러가지 대쉬보드에 구현가능한 모든 기능을 다넣어줘"

**뒷부분("모든 기능을 다넣어줘")은 사용자가 카탈로그로 결정**했다
(`docs/catalog/dashboard-features.md`·`settings-catalog.md`).
**이 Task는 앞부분 — "내가 말한 모든 것"의 설정화다.**

### 지금 상태

- [`settings/page.tsx`](../../apps/web/src/app/%28app%29/settings/page.tsx) 406줄.
- `FEATURES` **12종** 토글([`access.ts:31`](../../packages/core/src/domain/access.ts#L31)).
- 개별 설정 컴포넌트가 이미 여러 개: `AppearanceSetting` · `NotifySetting` ·
  `QuietHoursSetting` · `ThemeToggle` · `WalkingModeToggle` · `ProfileSettings`.
- **경계 규칙이 이미 코드에 박혀 있다**(1차 6-1): **설정 = 내 것(개인화) · 관리자 = 남의 것(권한)**.
  **이 규칙을 지킨다** — 어기면 두 화면이 다시 섞인다.

### 만들 것

Phase 42~48이 만드는 것마다 설정을 붙인다. **각 Phase가 자기 설정을 만들고 이 Phase가 모은다.**

| 출처 Phase | 설정 항목 |
|---|---|
| 42 | 뉴스 TOP3 기간(72시간 기본) |
| 43 | 새 페이지 기본 템플릿 · 새 페이지를 DB로 만들기 |
| 44 | 뽀모도로 알람음 선택·음소거 · 알림 팝업 켜기 · 메모 기본 색 · 캘린더 크기·지난 일정 표시 |
| 45 | 오리 자율 발화 빈도·끄기 · 날씨 사용 여부·지역 · 걷는 오리 끄기 |
| 46 | 통계 기본 기간 |
| 47 | 번역 켜기·끄기 · 요약 길이 |
| 48 | 오피스 줌 기본값 · 말풍선 표시 · 사운드 음소거 |

- **설정 검색을 넣는다.** 항목이 이만큼 늘면 찾을 수 없다.
- **카테고리 구조**로 나눈다(모양 · 알림 · 오리 · 위젯 · 뉴스 · 오피스 · 데이터 · 계정).
- **기본값이 지금 동작과 같아야 한다.** 설정을 도입하면서 기본값을 바꾸면
  **아무 조작도 안 한 사용자의 화면이 바뀐다** — 요청 없는 동작 변경이다.
- **저장은 한 경로로.** 지금 설정이 **localStorage와 DB에 흩어져 있다**
  (백업 v4가 localStorage까지 담게 된 이유). **어느 것이 어디 사는지 표로 정리하고 문서화한다** —
  안 하면 "설정을 바꿨는데 다른 기기에서 안 바뀐다"가 다음 피드백이 된다.

## T2 — 사용자별 개인화 + 관리자 권한 (6-2)

### 원문

> "사용자별 컨트롤할수있어야해 개인화가능해야하지 (색상변경, 연동 등 ) 만 글고
> 555jungs@gmail.com 관리자 권한도 줘야지 모든것을 쓸수있게"

### 지금 상태 (1차 6-2·6-3에서 만들었으나 **저장이 안 된다**)

- 역할 3종(ADMIN · USER · CUSTOMER) + RLS. **판정의 단일 출처는 RLS**, 화면은 숨기기만 한다.
- [`AdminUserPanel`](../../apps/web/src/components/AdminUserPanel.tsx)에서 사용자별 기능 토글.
- **전부 마이그레이션 대기.** T0이 풀어야 동작한다.

### 만들 것

- **"색상변경"** — 요청이 개인화의 예시로 명시했다. 지금 `ThemeToggle`(라이트/다크)만 있다.
  **강조색(accent) 선택**을 추가한다. CSS 변수(`--primary-accent`)가 이미 있어
  **토큰 하나를 바꾸면 전체가 따라온다** — 컴포넌트를 하나씩 고치지 않는다.
  - **대비를 검증한다.** 사용자가 흰색을 고르면 흰 배경에서 글자가 사라진다.
    **선택지를 검증된 팔레트로 제한**한다(자유 색상 선택기를 주지 않는다).
    [Phase 42 T6](phase_42.md)·[44 T3](phase_44.md)이 쓴 대비 검사와 같은 방식.
- **역할이 화면을 어떻게 바꾸는지 표로 못박고 테스트한다.**
  `hiddenHrefs`([`AppNav.tsx:112`](../../apps/web/src/components/AppNav.tsx#L112))가
  이미 서버가 정한 목록으로 메뉴를 숨긴다 — **클라이언트에서 권한을 다시 판정하지 않는다**
  (주석이 이미 그렇게 못박아 뒀다). **그 계약을 유지한다.**
- **관리자가 자기 권한을 스스로 뺄 수 없게 한다.** 마지막 관리자가 자신을 강등하면
  **아무도 관리자 화면에 들어갈 수 없다** — SQL로만 복구 가능한 상태가 된다.
  `ProfileSettings`가 이미 "역할 키를 아예 받지 않는다"로 한쪽을 막았다
  ([주석 15행](../../apps/web/src/components/ProfileSettings.tsx#L15)) — **관리자 패널 쪽도 막는다.**

## T3 — 양방향 계정 연결 (6-3)

### 원문

> "구글로 로그인해도 깃허브 잔디볼수잇게 깃허브 설정에서 연결하몀ㄴ 보이도록해주고
> 그 반대로도 가능하게해줘 )구글캘린더등)"

**요구가 명확하다**: 로그인 방식과 무관하게 **양쪽 연동을 다 쓸 수 있어야 한다.**

### 지금 상태 — 절반이 이미 있다

- **토큰 저장 구조가 core에 있다**: `githubOAuthToken` · `googleOAuthToken` · `gmailOAuthToken` 스키마.
- **GitHub 잔디**: [`GithubContributionWidget`](../../apps/web/src/components/GithubContributionWidget.tsx) + 캐시.
- **Google Calendar**: [`GoogleCalendarLink`](../../apps/web/src/components/GoogleCalendarLink.tsx) +
  로그인 시 Calendar scope 요청([`LoginForm.tsx:45`](../../apps/web/src/app/login/LoginForm.tsx#L45)).

**문제: 스코프를 로그인 시점에 받는다.** Google로 로그인하면 Calendar는 되고 GitHub는 안 된다.
GitHub로 로그인하면 그 반대다. **[Phase 41](phase_41.md)이 이메일 로그인을 추가하면
둘 다 안 되는 경우가 새로 생긴다** — 그래서 이 Task가 Phase 41의 필연적 후속이다.

### 만들 것

- **`supabase.auth.linkIdentity({ provider })`를 쓴다.** Supabase Auth의 **네이티브 기능**이다 —
  ponytail 사다리 4~5단계. **자체 계정 연결 테이블을 만들지 않는다.**
  - **[확인 필요]** 이 기능은 Supabase 프로젝트 설정에서 **Manual linking을 켜야** 할 수 있다.
    대시보드 확인이 필요하고, 그러면 T0과 같은 "사용자 실행" 항목이 하나 늘어난다.
- **설정 → 연동 화면**: Google · GitHub 각각 연결/해제 + 연결 상태 표시.
  연결하면 **그 연동이 필요한 위젯이 나타난다**(GitHub 잔디 · 캘린더).
- **연결 안 됐을 때 위젯이 조용히 비지 않게 한다.** "GitHub를 연결하면 커밋 잔디가 보여요" +
  연결 링크. 이 저장소 원칙: **정체 모를 실패 대신 왜 안 되는지 말한다.**
  `GithubContributionWidget`이 [빈 상태를 이미 처리](../Status.md)한다 — 그 자리에 연결 링크를 넣는다.
- **마지막 인증 수단을 해제할 수 없게 한다.** 유일한 로그인 수단을 해제하면 **계정에 들어갈 수 없다.**
  Phase 41의 이메일 로그인이 있으면 완화되지만, **비밀번호를 설정하지 않은 사용자**는 여전히 잠긴다.
  **해제 전에 다른 수단이 있는지 검사한다.**
- **토큰은 서버에만.** `NEXT_PUBLIC_` 금지. [Phase 35](phase_35.md)가 세운 키 유출 검사 방식
  (테스트가 클라이언트 번들 유입을 잡는다)을 **이 토큰들에도 적용한다.**

## 의존 계약

- **마이그레이션 6~7건 일괄 적용** — T0. **사용자만 실행 가능.**
- **신규 의존성 0개.** `linkIdentity`는 이미 설치된 SDK에 있다.
- **[Phase 42~48 의존]** T1이 모을 설정 항목은 그 Phase들이 만든다. **먼저 끝나야 한다.**
- **[Phase 41 의존]** T3은 이메일 로그인 이후의 계정 상태를 다룬다.

## 하지 않을 것

- **자체 계정 연결 테이블.** `linkIdentity`가 네이티브로 한다.
- **자유 색상 선택기.** 대비가 깨지고 글자가 사라진다.
- **설정 기본값 변경.** 요청 없는 동작 변경이다.
- **클라이언트에서 권한 재판정.** RLS가 단일 출처다(1차 6-3이 세운 계약).
- **관리자 화면에서 자기 역할 강등 허용.** 복구 불가 상태를 만든다.
- **마이그레이션을 임의 적용.** 두 경로 모두 차단됐고, DDL은 CLAUDE.md 5절이 사용자 확인을 요구한다.
