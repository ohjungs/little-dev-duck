# Phase 48 — 오피스를 실제 업무와 잇는다 (5-1 ~ 5-5)

> 상태: **draft(예약·미착수)**
>
> 착수 전 stale 가드:
> ① `simulateNpcTasks`(가짜 업무 생성기)가 아직 삭제된 상태인가(1차 5-7에서 지웠다 — 되살아나면 안 된다)
> ② 오피스 작업 원천이 아직 "할 일·페이지·습관·일정·뽀모도로" 전부를 직무 구분 없이 쓰는가
> ③ `PixelOffice.tsx`가 아직 1410줄인가
> ④ `OfficeTalkPanel`이 아직 클릭 시에만 대화를 보여주는가

## 왜 이 일인가

**1차 피드백에서 오피스 7항목을 전부 처리했는데 2차에 5항목이 또 올라왔다.**
그런데 성질이 다르다 — **1차는 "가짜를 없애라", 2차는 "진짜와 이어라"다.**

| 1차 (완료) | 2차 (이번) |
|---|---|
| 5-7 가짜 업무 생성기 삭제 | 5-1·5-3 **직무별로 다른 원천 매핑** |
| 5-3 일 안 하면 "쉬는 중" | 5-2 **누르면 실제 무슨 일인지** |
| 5-4 원천을 앱 내부 작업으로 합의 | 5-4 **말풍선으로 상시 표시** |
| 5-5 게임 요소 제거 | 5-5 **화면 확대 + 기능 확대** |

**1차가 뺄셈이었고 2차가 덧셈이다.** 순서가 맞다 — 가짜를 지운 자리에 진짜를 넣는다.

---

## ⚠ 요청 안의 긴장 — 해석을 먼저 못박는다

**5-1은 "빼라"고 하고 5-5는 "최대한 많이 넣어라"고 한다.**

> 5-1: "기존에 습관 + 일기 +할일 이런거는 개발자가 일하는것처럼 만들필요없고
> 실제로 **"개발" 건에 대해서만** 개발자가 적용하게하고"
>
> 5-5: "화면이 너무작아서 좀더 크고 다양한 기능을 넣어줬으면 좋겠어 **최대한 많은 기능**을 넣어줘"

**해석**: 5-1은 **매핑의 정확성**(엉뚱한 직무에 엉뚱한 업무를 붙이지 마라),
5-5는 **화면과 조작의 확대**(작아서 답답하다)다. 충돌하지 않는다.

**5-5를 "새 게임 요소 추가"로 읽으면 1차 5-5(게임 요소 제거)와 정면 충돌한다** —
그렇게 읽지 않는다. **재정 시뮬·급여·만족도·평판·MVP를 되살리지 않는다.**

## T1 — 직무별 작업 원천 매핑 (5-1 + 5-3, 같은 요청이다)

### 지금 상태

1차 5-4에서 **"원천은 앱 내부 작업 상태로 합의"**했다 — 할 일 · 페이지 · 습관 · 일정 · 뽀모도로.
**그런데 직무 구분 없이 쓴다.** 그래서 개발자 오리가 "습관 체크"를 하고 있다.
사용자가 그걸 봤다.

### 만들 것

**직무 → 원천 매핑을 core에 데이터로 둔다.**

| 직무 | 원천 (요청이 명시한 것) | 근거 |
|---|---|---|
| **개발자** | **"개발" 건만** — GitHub 커밋·이슈·PR · Claude Code 로그 · 개발 관련 할 일 | 5-1·5-3 원문 |
| **인사팀** | **"진짜 내가 해야 할 일들"** — 할 일 · 일정 · 마감 | 5-3 원문 |
| 기획/문서 | 페이지 작성·편집 | [추정] |
| 나(사장) | 뽀모도로 · 습관 | [추정] — 개인 루틴은 남에게 위임할 성질이 아니다 |

- **"개발 건"을 무엇으로 판정하나 — 이게 핵심이고 함정이다.**
  - **GitHub 데이터는 이미 있다**: [`GithubContributionWidget`](../../apps/web/src/components/GithubContributionWidget.tsx)이
    잔디를 가져오고 캐시까지 한다. [`GitHubIssuesLink`](../../apps/web/src/components/GitHubIssuesLink.tsx)도 있다.
    **재구현 금지 — 그 경로를 쓴다.**
  - **Claude Code 로그 수집기가 Tauri Rust 쪽에 있다**(ARCHITECTURE.md 1절 — "Rust 사이드 =
    Claude Code 로그 수집기"). [`DesktopCollectorSync`](../../apps/web/src/components/DesktopCollectorSync.tsx)가
    그걸 받는다. **[확인 필요] 실제로 무엇이 들어오는지 세어 본다** —
    이게 5-4("실제 개발중인 서버와 연결")의 가장 진짜에 가까운 답이다.
  - **할 일 제목으로 "개발"을 판정하지 않는다.** 키워드 매칭은 오탐이 크고,
    사용자가 제목을 어떻게 쓰는지 우리가 정할 수 없다.
- **매핑에 해당 업무가 없으면 "쉬는 중"이다** — 1차 5-3이 세운 계약. **유지한다.**
  **없는 업무를 만들지 않는다** — `simulateNpcTasks`를 다시 만드는 순간 1차 5-7로 되돌아간다.
  **그 함수가 되살아나지 않는지 테스트로 잠근다.**

## T2 — 직원을 누르면 실제 작업 보기 (5-2)

### 원문

> "사장실에서 전사 대시보드 볼때 직원을 누르면 진짜 어떤일을 하고있는지 볼수있도록 기능 넣고"

### 만들 것

- 직원 클릭 → **상세 패널**: 지금 하는 일 · 원천(어느 데이터에서 왔는지) · 최근 활동 목록 · 상태.
- **"원천을 밝히는 것"이 이 Task의 핵심이다.**
  사용자가 1차에서 "**일하는 척**"을 지적했다(5-7). 상세를 보여줘도 근거가 없으면
  같은 의심을 받는다. **"GitHub 커밋 3건" / "할 일 '로그인 고치기'"처럼 실물을 보여준다.**
  누르면 **그 원본으로 이동**한다(할 일 위젯 · GitHub 링크 · 페이지).
- [`OfficeDashboard`](../../apps/web/src/components/OfficeDashboard.tsx)(135줄)와
  [`OfficeManagementPanel`](../../apps/web/src/components/OfficeManagementPanel.tsx)(239줄)이 이미 있다 —
  **어디에 붙일지 먼저 확인하고, 새 패널을 만들지 판단한다.**
- 키보드로도 선택·열기가 되어야 한다(오피스는 캔버스라 접근성이 특히 잘 빠진다).
  [`VirtualDpad`](../../apps/web/src/components/VirtualDpad.tsx)가 이미 있다.

## T3 — 말풍선 상시 + 상호작용 발화 (5-4)

### 원문

> "직원들은 대화 말풍선으로 계속 말하게해주고 상호작용하면 말하게해줘"

### 만들 것

- **상시 말풍선**: 각 직원 머리 위에 지금 하는 일을 짧게. 상호작용 없이도 보인다.
- **상호작용 발화**: 인접해서 상호작용하면 더 긴 대화.
  [`isAdjacent`](../../packages/core/src/domain/office-play.ts)·`describeActivity`가 이미 core에 있다 —
  **재구현 금지.**
- **⚠ "계속 말하게"의 함정 — 1차 5-7을 되풀이하지 않는다.**
  말풍선을 채우려고 문장을 **생성**하면 그게 정확히 "일하는 척"이다.
  - **실제 업무가 있을 때만 그 업무를 말한다.**
  - 업무가 없으면 **"쉬는 중"을 말하거나 말풍선을 띄우지 않는다.**
  - **[Phase 45](phase_45.md)의 LLM을 여기 쓰고 싶어질 것이다 — 신중하게.**
    직원 수 × 갱신 빈도만큼 호출이 발생한다. **쿼터가 즉시 터진다.**
    LLM을 쓴다면 **표현만**(사실은 우리가 주고), **캐시**하고, **상한**을 둔다.
    **[추정] 이 자리는 템플릿이 맞다** — 문장이 짧고 정보 전달이 목적이다.
- 말풍선이 **서로 겹치지 않게** 배치한다. 겹치면 읽을 수 없고, 그게 "UI가 이상해"가 된다
  (1차 5-2에서 자산이 벽을 넘던 것과 같은 부류).
- **모션 축소 설정을 존중한다**(`prefers-reduced-motion`).

## T4 — 화면 확대 (5-5)

### 원문

> "화면이 너무작아서 좀더 크고 다양한 기능을 넣어줬으면 좋겠어 최대한 많은 기능을 넣어줘"

### 만들 것

- **[확인 필요] 무엇이 작은지 먼저 실측한다.** 셋 중 하나다:
  (가) 캔버스 픽셀 크기가 작다 · (나) 타일이 작아 오리가 작게 보인다 ·
  (다) 보이는 방 범위가 좁다.
  **[추정] (나)+(다)** — 타일 32px에 카메라 줌이 고정이면 그렇게 느껴진다.
  [`createCamera`·`visibleTileRange`](../../packages/core/src/domain/office-camera.ts)가 이미 있다.
- **줌 조절**(3단계) + **캔버스를 화면에 맞게 확대**. 전체화면 버튼.
  - **⚠ 1차 5-2의 함정을 반복하지 않는다**: 자산 43개 중 **32×32를 64×64로 그리던 버그**로
    "벽을 넘어가는" 문제가 났다. **줌을 넣으면 그 스케일 계산이 다시 위험해진다.**
    **자산 원본 크기와 타일 크기의 관계를 테스트로 잠근다.**
  - 정수 배율(1x·2x·3x)만 쓴다 — 소수 배율은 픽셀 아트를 뭉갠다(사용자가 다른 항목에서
    "뭉개진다"를 이미 지적했다).
- **"다양한 기능"** — 5-1의 제약(가짜·게임 요소 금지) 안에서:
  미니맵 · 직원 목록 사이드바에서 클릭 이동 · 방(zone)별 이동 · 상태 필터
  (일하는 직원만 보기) · 오늘 활동 요약. **전부 이미 있는 데이터의 다른 표현이다.**
  → **새 데이터·새 게임 요소를 만들지 않는다.**

## 의존 계약

- **신규 의존성 0개.** 캔버스·카메라·타일맵·상호작용이 전부 core에 있다.
- **마이그레이션 0개.** 전부 기존 데이터의 재해석·재표현이다.
- **[Phase 41 의존]** 오피스는 로그인 뒤 화면이고 **캔버스라 정적 분석으로 검증이 거의 안 된다.**
  44건이 켜지지 않으면 이 Phase의 검증은 매우 약하다. **가장 Phase 41이 필요한 Phase다.**
- **`PixelOffice.tsx`가 1410줄이다** — 이 저장소에서 가장 큰 컴포넌트다.
  이 Phase가 그 안을 여러 군데 건드리므로 **말풍선·상세 패널·줌 컨트롤을 별 파일로 분리**한다.
  파일이 크면 편집이 불안정해진다.

## 하지 않을 것

- **`simulateNpcTasks` 부활 또는 유사물.** 1차 5-7의 정확한 재발이다. **테스트로 잠근다.**
- **재정·급여·만족도·평판·MVP·"수고했어" 부활.** 1차 5-5에서 지웠다.
- **말풍선을 채우기 위해 문장을 생성하는 것.** 없는 업무를 지어내는 것과 같다.
- **직원마다 LLM 호출.** 쿼터가 터진다.
- **소수 배율 줌.** 픽셀 아트가 뭉개진다.
- **할 일 제목 키워드로 "개발 건" 판정.** 오탐이 크다.
