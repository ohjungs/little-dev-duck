# Phase 22 — 스키마 안전 계약을 자동 검사로 잠그기

착수 근거: `/loop-eng` SCOPE(5장). Phase 21 소진 → 신규 로드맵 발굴.

## 발굴 방식 — 막혀 있는 점검을 코드로 대신할 수 있는 만큼 가져온다

Supabase 보안·성능 어드바이저는 액세스 토큰이 없어 **세 사이클 연속 실행하지 못했다**
(manual-verification 13번). 그렇다고 "괜찮을 것"이라고 적을 수는 없다.

그런데 어드바이저가 보는 것 중 **마이그레이션 파일만 읽어도 결정적으로 판정 가능한 항목**이
있다. 이번 사이클에 그 검사를 손으로 돌려 봤고, 결과는 이렇다.

| 검사 | 결과 |
|---|---|
| 테이블 19개 전부 RLS 켜져 있나 | **통과** — 누락 0건 |
| RLS 켜고 정책 0건인 테이블(전면 차단) 있나 | **통과** — 0건 |
| 마이그레이션마다 down 스크립트 있나 | Phase 20에서 5건 누락 발견·보충 → 현재 통과 |
| 계정 데이터 파기가 모든 테이블을 덮나 | `page_links`가 목록에 없음 → **연쇄 삭제로 덮이는 것 확인**(오탐 아님) |

**손으로 돌린 검사는 다음에 또 새는다.** down 스크립트 5건이 실제로 그랬다 — 규칙은
CLAUDE.md 5절에 적혀 있었는데 아무도 확인하지 않아 조용히 빠졌다. 검사를 테스트로 만들어
CI에 올리면 같은 일이 반복되지 않는다.

이게 "새 기능"은 아니지만, 지금 이 저장소에서 가장 값이 큰 일이다. 기능은 이미 많고
(FEATURES MUST 잔여 0건, VOC 잔여 0건), 무너지면 가장 비싼 건 데이터 안전이다.

## 중복 방지 확인

- 기존 테스트는 전부 **애플리케이션 코드**를 대상으로 한다. **마이그레이션 SQL 자체를
  검사하는 테스트는 0건**(`supabase/` 경로를 읽는 테스트 파일 없음).
- 순수 로직 테스트 추출은 이미 포화다 — web lib 미테스트 6개는 전부 canvas/DOM/Supabase
  realtime이고, api 미테스트 1개(`oauthTokens.ts`)는 google·github·gmail 토큰 테스트가
  팩토리를 통과하며 이미 덮는다. core 미테스트 2개는 상수·스키마 선언뿐이다.

## 설계 결정 (ponytail 7단계)

- **새 도구·의존성 없이** 기존 vitest로 한다. SQL 파서를 들이지 않고 정규식으로 읽는다 —
  검사 대상이 우리가 직접 쓴 마이그레이션이라 문법 변주가 좁다.
- **`packages/api`에 둔다.** DB 접근을 소유한 패키지이고, `turbo test` → CI에 자동으로 실린다.
  루트에 별도 스크립트를 만들면 CI에 따로 배선해야 한다(설정 하나 더 = 또 하나의 드리프트 지점).
- 경로는 cwd가 아니라 **파일 기준**(`import.meta.url`)으로 잡는다. cwd에 의존하면 실행 위치가
  바뀌는 순간 조용히 0개 파일을 읽고 "전부 통과"가 된다 — 검사가 통과를 가장하는 최악의 실패다.
- **연쇄 삭제(cascade)를 계산에 넣는다.** `page_links`는 파기 함수 목록에 없지만
  `pages(id) on delete cascade`라 함께 사라진다. 단순히 "목록에 있나"만 보면 오탐이 나고,
  오탐 나는 검사는 곧 무시된다.
  - 단, **`auth.users` 참조 cascade는 인정하지 않는다.** 파기 함수는 계정(profiles)을 남기고
    데이터만 지우는 설계라 auth.users는 삭제되지 않는다 — 그 cascade는 발동하지 않는다.

## Task

### T1 스키마 안전 계약 검사 (api, 결정적)
- **수용 기준**:
  - 마이그레이션에서 만든 모든 테이블에 `enable row level security`가 있다.
  - RLS를 켠 테이블에는 정책이 최소 1건 있다(켜 놓고 정책이 없으면 본인 데이터도 못 읽는다).
  - 모든 마이그레이션 파일에 짝이 되는 `supabase/rollback/<name>_down.sql`이 있다.
  - `user_id`를 가진 모든 테이블이 계정 데이터 파기로 사라진다 — 함수가 직접 지우거나,
    지워지는 테이블로 향하는 `on delete cascade` 경로가 있거나.
  - **검사가 실제로 파일을 읽었는지 자체 확인**한다(0개를 읽고 통과하는 일이 없도록).
- **의존 계약**: 코드 변경 없음. 마이그레이션·롤백 파일만 읽는다.

### T2 검사가 잡아내는지 확인 (메타 검증)
- **수용 기준**: 위 규칙 각각에 대해, 규칙을 어기는 가짜 입력을 주면 검사가 **실패**하는지
  확인한다. 검사 로직을 순수함수로 분리해 가짜 입력을 넣어 본다.
  — 통과만 확인하고 넘어가면 "아무것도 안 잡는 검사"가 통과로 위장한다.
