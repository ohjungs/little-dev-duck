## 왜 이 Phase가 가장 큰가 (82항목)

**이 제품에만 있는 부분이 여기 모여 있다.** 다른 메신저에는 오리 마스코트도, 픽셀 오피스도,
LLM 에이전트 팀도 없다. 카탈로그가 R 섹션 머리말에 적은 것이 이 Phase 전체에 적용된다:

> "이 카테고리가 LDD에서 메신저를 만들 **실제 명분**이다."

**그런데 82항목 중 77개가 DEFER다.** 즉 **하나도 급하지 않고, 전부 만들면 안 된다.**
이 Phase의 성격은 "다 만든다"가 아니라 **"제품 정체성에 기여하는 것만 고른다"**다.

---

## ⚠ 이 Phase에는 코드로 풀 수 없는 선행 결정이 있다 — 오리 그림

[PENDING 4번](../loop-eng/PENDING.md)이 이미 같은 벽에 막혀 있다:

> `duck_state.costume` 컬럼이 있고 "먹이"는 코스튬 구매 재화이며 `DECISIONS.md`도
> "코스튬은 레벨 해금 + 먹이 구매"로 확정해 뒀는데 **저장만 되고 아무 데서도 읽히지 않는다.**
> 오리는 스프라이트 한 장으로 그려지므로 코스튬에는 **새 그림이 필요**하고,
> **오리 외형은 사용자가 직접 만들어 넣어 온 영역이라 임의로 만들지 않았다.**

**이 Phase의 다음 항목들이 전부 같은 벽에 막힌다:**

| 항목 | 필요한 것 |
|---|---|
| D-008 애니메이션 프로필 (GLB) | 3D 모델 |
| D-010 코스튬 반영 · Y-010 코스튬 채팅 프로필 | **코스튬 그림** (PENDING 4번) |
| D-011·Y-003·Y-006 감정·표정 상태 | **표정 스프라이트 세트** |
| Y-016 마스코트 스티커 세트 자동 생성 | **표정 세트** |
| Y-020 특별한 날 연출 | 연출 자산 |

> **착수 전에 PENDING 4번을 먼저 닫아야 한다.** 닫히지 않으면
> **이 Phase의 약 12개는 만들 수 없다** — 그림 없이 코드만 만들면 빈 슬롯이 남는다.
> 그건 "만들었는데 아무것도 안 보인다"가 되고, 사용자가 이미 지적한 부류다.

**결정 없이 만들 수 있는 것부터 한다** — 아래 T1·T4·T5.

## T2 — 프로필 심화 (D 23항목) — 일부는 그림 대기

- 이미지 크롭·리사이즈(D-003) · 배경(D-005) · 미리보기(D-006) · 이미지 히스토리(D-007) ·

  소식 피드(D-019~D-022) · 목록/피드 뷰 선택(D-024) · 배지(D-025) ·
  접속 상태 숨기기(D-028) · 커스텀 상태(D-029) · 뽀모도로 상태 자동 전환(D-030).
- **D-030은 기반이 있다** — `FOCUS_MODE_KEY`가 집중 상태를 이미 안다. **연결만 한다.**
- **D-023(피드형 목록 뷰 강제)이 SKIP인 근거가 특히 좋다** — 카탈로그가
  "카카오도 3개월 만에 철회함, **학습된 실패 사례**"라고 적었다. **그 판단을 유지한다.**

- **D-013·D-014 공개 범위는 S3(실제 멀티 유저) 전용이다.** [Phase 53](phase_53.md)의
  시나리오 결정에 딸린다 — 혼자 쓰면 만들 값이 없다.
- **D-019~D-022 소식 피드는 이 제품의 범위를 벗어난다.** 메신저가 SNS가 된다.
  **[확인 필요] 원하는지 확인하고, 아니면 닫는다.** 만들면 큰 기능이다.

## T3 — 마스코트 (Y 15항목) — 대부분 그림 대기

- 표정 상태 머신(Y-003) · 커서 추적(Y-004) · 유휴 코딩 애니메이션(Y-005) ·

  사운드 효과·끄기(Y-017·Y-018) · 색상 연동(Y-019) · 특별한 날(Y-020).
- **Y-007 XP는 이미 있다** — `award_xp` RPC + `emitXpChanged`.
  **대화량으로 XP를 주는 것은 연결만 하면 된다.** 다만 **⚠ `award_xp` 권한 결함이
  미적용 마이그레이션에 걸려 있다**([PENDING 1번](../loop-eng/PENDING.md) — 지금 열려 있는 구멍).

  → **[Phase 45](phase_45.md) 예산에서 배분받고, 캐시하고, 상한을 둔다.**
  **[추정] 규칙 기반(이모지·느낌표·부정어)으로 대부분 되고 그게 훨씬 싸다** — HD-003.
- **Y-017·Y-018 사운드**: [Phase 44](phase_44.md)가 음원 자산과 음소거 설정을 정리한다.
  **그걸 쓴다.** 이 저장소는 **사인파 사운드로 이미 지적받았다**(1차 5-1).

## T4 — 에이전트 심화 (R 12항목)

- **다중 에이전트 그룹방(R-021)·에이전트 간 릴레이(R-022)가 이 제품의 가장 독특한 기능이다.**
  CLAUDE.md 3-2의 **PDCA 팀**(Plan/Do/Check/Act)이 그대로 채팅방이 된다.
  - [Phase 53](phase_53.md)의 그룹방 위에 얹는다.
  - **⚠ 에이전트 간 릴레이는 무한 루프가 된다.** A가 B에게 말하고 B가 A에게 답하면 끝이 없다 —
    **턴 상한을 두고, 쿼터를 태우기 전에 멈춘다.** 이게 이 Task에서 가장 위험한 부분이다.
  - **사람이 개입해 멈출 수 있어야 한다.**
- 작업 상태 표시(R-023) · 백그라운드 결과 푸시(R-024) · 대화 요약·회고(R-026) ·
  응답 스타일 프리셋(R-030) · 모델 선택(R-031) · 프롬프트 템플릿(R-032) ·
  대화 분기(R-033) · 응답 평가(R-034) · 인사 감지(R-029) · 감정 표정(R-028).
- **R-023·R-024는 [Phase 48](phase_48.md)과 같은 것이다** — 오피스 직원의 작업 상태.
  **한쪽에서만 만든다.** 오피스가 이미 "실제 업무만 보인다"는 계약을 세웠으니 **그걸 따른다** —
  **없는 작업을 지어내면 1차 5-7의 재발이다.**
- **R-031 모델 선택**: 무료 티어 안에서만. **모델 이름을 화면에 노출하면
  나중에 모델이 바뀔 때 거짓이 된다** — 성격("빠름/자세히")으로 표현하는 편이 안전하다.
- **R-029 인사 감지는 `last_seen_at`이 필요하다** — [Phase 51](phase_51.md)의 D-027에서 들어온다.
