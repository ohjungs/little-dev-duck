# Phase 29 — 내보낸 백업이 실제로 백업인가 (데이터 이식성)

> 상태: draft(예약·미착수) — 2026-07-26 `/loop-eng` 버퍼(5-A)로 생성
> 착수 직전 stale 가드 필수: 아래 "확인된 사실"을 다시 재고 시작한다.

## 왜 이 일인가

설정 화면의 **"내 데이터 내보내기"** 버튼은 사용자에게 백업을 약속한다.
그런데 실제로 나가는 JSON을 코드로 따라가 보니 **문서 본문이 한 글자도 들어가지 않는다.**
사용자는 백업했다고 믿고 있고, 그 믿음이 틀렸다는 걸 알 방법이 없다.

Phase 26과 같은 부류다 — "기능은 있는데 실제로는 동작하지 않는" 상태.

## 확인된 사실 (2026-07-26 코드로 확인, 추측 아님)

| 항목 | 상태 | 근거 |
|---|---|---|
| 페이지 **본문**(`pages.content` jsonb) | **빠짐** | `listPages`의 select에 `content` 없음(pages.ts:70). `ExportDataButton`은 그중 `id·title·icon·updatedAt` 4개만 담음(ExportDataButton.tsx:31-36) — `plain_text`조차 버린다 |
| 캘린더 일정(`calendar_events`) | **빠짐** | 내보내기가 `listTodos·listMemos·listHabits·listPages` 4개만 호출 |
| 습관 **체크 기록**(`habit_checks`) | **빠짐** | `listHabits`는 `habits` 테이블만 조회(habits.ts:52). 스트릭·수행 이력이 통째로 사라짐 |
| 되가져오기(import) | **없음** | 내보낸 JSON을 되돌리는 경로가 저장소에 없다. 파일 가져오기는 `decodeTextFile`(페이지 본문 텍스트)뿐 |
| 조회 상한 | 500건 | `listPages`·`listHabits` 모두 `.limit(500)` — 넘으면 **조용히 잘린다** |

**즉 현재 내보내기는 "제목 목록 + 할 일 + 메모"이고, 복원 수단이 없다.**

## Task

- **T1 — 내보내기에 빠진 데이터를 채운다.**
  - 수용 기준: 내보낸 JSON에 페이지 본문(`content`)·캘린더 일정·습관 체크 기록이 포함된다.
  - 500건 상한에 걸리면 **조용히 자르지 않고** 사용자에게 알린다(잘린 백업은 백업이 아니다).
  - 주의: `listPages`의 select를 넓히면 **Cmd+K 검색·목록 조회의 전송량이 커진다.**
    내보내기 전용 조회를 따로 둘지, 공용 조회를 넓힐지는 착수 시 판단(전자가 유력 — 목록
    화면이 본문 jsonb를 매번 받을 이유가 없다).

- **T2 — 되가져오기(import).**
  - 수용 기준: T1이 내보낸 파일을 그대로 넣으면 항목이 복원된다(라운드트립 테스트로 잠금).
  - **되돌리기 어려운 작업이다.** 기존 데이터 덮어쓰기는 하지 않고 **추가(merge)만** 한다.
    같은 id가 이미 있으면 건너뛴다(멱등). 실행 전 확인 다이얼로그 — CLAUDE.md 5절.
  - 한글 깨짐은 이미 겪은 부류(commit 0ddcf12) — `decodeTextFile`의 인코딩 처리를 재사용한다.

- **T3 — 라운드트립 회귀 테스트.**
  - 내보내기 → 가져오기 → 다시 내보내기 결과가 동일한지. 순수 함수로 분리해 로그인 없이 검증.

## 의존 계약

- 신규 core 타입: 내보내기 파일 스키마(zod) — **버전 필드 필수.** 형식이 바뀌면 옛 백업을
  거부할지 변환할지 결정 가능해야 한다.
- DB 마이그레이션 **불필요**(기존 테이블 조회만).
- `packages/api`에 내보내기 전용 조회 추가 가능성(T1 판단에 따라).

## 슬라이스 순서

T1(내보내기 채우기, 단독으로도 가치 있음) → T3 스키마·테스트 → T2(가져오기).
T1만 해도 "백업이 실제로 백업이 된다"는 값이 나오므로 여기서 끊어도 된다.

## 미착수 근거로 남긴 것

- 자동 백업·클라우드 동기화: 무료 원칙상 서버 스케줄러가 없다(Phase 20에서 확인된 제약).
- 다른 서비스(노션 등) 형식으로의 내보내기: 수요 근거 없음. YAGNI.
