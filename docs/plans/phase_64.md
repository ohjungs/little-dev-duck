> 않는다. 메신저 실사용화(오리 응답)의 품질 후속이며, 패널·메신저 공통 개선이다.

## 방향

- **계약 변경은 병렬 구간 밖 단독 커밋으로**(CLAUDE.md 3-3): 요청 스키마에
  `history?: { role: "user" | "duck"; content: string }[]`를 추가하되 **엄격 상한**
  (최근 6턴, 턴당 500자 — zod로 자르지 않고 거부 대신 서버에서 절단 명시)으로 토큰·쿼터를
  보호한다. history 없는 기존 호출은 그대로 동작(하위호환).
- 프롬프트 주입은 packages/ai의 기존 턴 조립(runDuckTurn/buildRagPrompt 계열)에
  "직전 대화" 절을 추가 — RAG 검색어는 여전히 최신 question 기준(검색까지 6턴을 섞으면
  잡음이 늘고 쿼터가 낭비된다).

## Task

### T1 — 서버 계약 + 프롬프트 (core/ai, STDD)
- 요청 zod: history 형식·상한 검증. core 순수 함수 `clampHistory(history, {turns, chars})`
  테스트 잠금(초과 절단·역할 검증·빈 배열).
- 프롬프트: 직전 대화 절 주입. rule 라우팅(인사 등)은 최신 발화만 본다(기존 유지).
- AC: history 미포함 요청은 기존과 동일 응답 경로. 상한 초과는 오래된 턴부터 절단.

### T2 — 대시보드 오리 패널 연결
- useDuckChat: 보낼 때 최근 대화(자체 messages 상태)에서 history 구성.
- AC: "그거/방금" 지시어 후속 질문이 맥락으로 이어진다(실기 확인 항목).

### T3 — 메신저 오리 방 연결
- MessageRoom.requestDuckReply: 방의 최근 메시지(text만, system 제외)에서 history 구성 —
  transcript 발화자 판정 한 벌 재사용 검토.
- AC: 오리 방에서 후속 발화 성립(실기 확인 항목).

## 유의
- Gemini 쿼터: 턴당 입력 토큰 증가(상한으로 캡). 무료 티어 예산 내 — 상한이 그 보증이다.
- 실기 검증 의존 큼(응답 품질) — 무인 구현 후 mv 항목으로 보류하는 표준 경로.
