# Phase 19 — 사용자가 실제로 요청한 미완 항목 (VOC 주도 SCOPE)

착수 근거: `/loop-eng` SCOPE(5장). Phase 18(공유·성장 루프) 전 Task 소진 → 신규 로드맵 발굴.

## 발굴 방식 — 마케팅 프레임워크 대신 실제 VOC를 썼다

5장은 marketing-skills(AARRR·아이디어 라이브러리) 주도를 기본으로 하지만, 이 저장소에는
`docs/feedback-2026-07-25.md`에 **사용자가 라이브 사이트를 직접 리뷰하며 남긴 실제 피드백**이 있다.
customer-research 스킬의 목적 자체가 VOC 마이닝이고, 추측으로 만든 후보보다 사용자가 말로 요구한
미완 항목이 우선한다(우선순위: 사용자 지시 > 이 커맨드). Phase 18은 사용자 데이터가 없어 AARRR
격차로 추론했지만, 이번엔 근거가 있으므로 그걸 쓴다.

## 중복 방지 확인 (재구현 금지 — 이번 세션에 2회 위반한 이력 있음)

착수 전 실제 코드로 확인한 것:

| 후보 | 현재 상태 | 판정 |
|---|---|---|
| 오리 대화 앱 액션 | `appActions.ts`에 createTodo·createMemo·createPage·completeTodo·addCalendarEvent **5종 존재, 전부 mutating** | 습관 체크만 없음 → T1 |
| 습관 체크 액션 | 없음. 피드백 iter11에 "습관 체크 … 후속"으로 **명시적 미완** | **신규** |
| 뉴스 주제 필터·큐레이션 | `news.ts`·`api/news.ts`에 topic/주제/카테고리 문자열 0건 | **신규** → T2 |
| 조회(readonly) 도구 | 없음. 단, RAG가 이미 항목을 답변에 surface(iter21) | **탈락** — 중복 가치 낮음 |

| 뽀모도로 시작 액션 | 클라이언트 타이머 | **탈락** — 서버 어댑터 사정권 밖 |

| 오피스 실 에이전트 백엔드 | Tauri sidecar 필요 | **backlog** — 대규모·사용자 인프라 |

## Task

### T1 오리 대화 — 습관 체크 액션 (VOC 명시 미완)
피드백 iter11: "할일 완료 처리·**습관 체크** 등 … 후속". 할일 완료(completeTodo)는 iter14에 됐고
습관만 남았다.
- **수용 기준**:
  - "운동 체크해줘", "오늘 독서 했어" → 제목(일부 일치)으로 습관을 찾아 **오늘 날짜로** 체크.
  - 이미 오늘 체크된 습관이면 에러가 아니라 "이미 체크됨"으로 답한다(멱등).
  - 제목이 안 맞으면 후보를 알려주고 아무것도 바꾸지 않는다. 여러 개 매칭되면 실행하지 않고 되묻는다
    (엉뚱한 습관을 체크하는 것보다 낫다).
  - mutating → 기존 승인 게이트를 그대로 탄다. 승인 카드에 대상 습관명이 보인다.
- **의존 계약**: 기존 `appActions.ts` 도구 카탈로그 + `checkHabit`/`listHabits`(api에 이미 있음).
  새 마이그레이션·새 스키마 없음. 매칭 로직은 core 순수함수로 추출 + STDD.

### T2 뉴스 주제별 추천 피드 (VOC — C절 "주제별 큐레이션")
피드백 C: "주제별(IT/주식/부동산/AI) 큐레이션 피드 추천은 좋은 RSS 목록 필요라 별도."
- **수용 기준**:
  - core에 주제별 추천 피드 목록(순수 데이터). 주제는 개발/AI 등 **이 제품 사용자에게 맞는 것만** —
    주식·부동산은 신뢰할 만한 무료 RSS를 자율로 고를 근거가 없어 넣지 않는다(정직).
  - 뉴스 화면에서 "추천 피드" → 1클릭 추가. 이미 등록된 피드는 중복 표시하지 않는다.
  - 기존 `addFeed`(SSRF 가드 포함) 재사용 — 새 서버 계약 없음.
- **의존 계약**: core `news-feeds.ts`(순수 목록 + 중복 제외 함수, STDD). api 변경 없음.
