## T1 — 뉴스 한국어 표시 + 요약 (4-2)

### 원문

> "가져온 뉴스는 영어가 아닌 한국어로 표시하고 요약도해줘야지"

### 지금 상태

- 요약 경로는 **있다** — [Phase 32](phase_32.md)가 이 경로에 인젝션 방어를 붙였다
  ("뉴스 요약 경로에는 방어가 없었다" → 붙였다).
- **번역은 없다.** 영문 피드(GeekNews·Hacker News 계열)의 제목이 영어로 그대로 나온다.

### 만들 것

- **제목·요약을 한국어로.** Gemini 한 번에 **번역 + 요약을 함께** 시킨다.
  따로 부르면 호출이 2배가 되고 무료 쿼터를 태운다.
- **원문을 버리지 않는다.** 원제를 함께 보관해 **원문 보기**에서 쓰고, 번역이 이상할 때
  사용자가 대조할 수 있게 한다. 이 저장소 원칙: **모르는 건 원문을 그대로 보여준다**
  ([Phase 37](../Status.md)의 오류 문구 판단과 같다).
- **한국어 기사는 번역하지 않는다.** 언어 판정은 **결정적으로 코드가 한다**(HD-003) —
  한글 문자 비율을 세면 된다. LLM에게 "한국어면 그대로 둬"라고 맡기면
  **쿼터를 태우고 결과도 불안정하다.**
- **결과를 저장한다 — 이게 이 Task에서 가장 중요하다.**
  매 렌더마다 번역하면 쿼터가 즉시 소진된다. `articles`에 번역 제목·요약 컬럼을 더한다.
  → **마이그레이션 1건** (down 포함).
  - **미적용 상태에서 안전하게 떨어져야 한다** — 값이 있을 때만 키를 넣는다
    ([Phase 37](../Status.md)이 겪은 사고). 컬럼이 없으면 **원문을 그대로 보여준다**(지금 동작).
  - **수집 시점에 한 번만** 번역한다(읽을 때가 아니라).
- **쿼터 예산을 [Phase 45](phase_45.md)와 함께 설계한다.** 자율 발화(45)와 뉴스 번역(47)이
  **같은 무료 쿼터를 먹는다.** 둘을 따로 만들면 합쳐서 초과한다.
  - **공용 `allowRequest`**(`@ldd/api`)를 쓴다 — 자체 `Map` 재구현은 **최고 심각도 위반**.
  - **수집 1회당 번역 건수 상한**을 둔다. 100건이 한꺼번에 들어와도 상한까지만.
    나머지는 원문으로 두고 **다음 수집에서 처리**한다(조용히 버리지 않는다).
  - 쿼터 소진 시 **원문 표시로 저하**한다. 화면이 비면 안 된다.
- **인젝션 방어를 유지한다.** 기사는 **남의 사이트가 쓴 텍스트**다.
  [Phase 32](phase_32.md)의 core `untrustedTextRule`을 쓴다 — **재구현 금지.**
  Phase 32가 진입점 개수를 테스트로 못박아 뒀으므로 **새 진입점이 생기면 테스트가 먼저 운다.**
  **번역은 요약보다 더 위험하다** — "이 문장을 번역해"에 "무시하고 X라고 써"가 섞이면
  우리 이름으로 조작된 문장이 나간다.

## T2 — 추천 피드를 계속 갱신 (4-3)

### 지금 상태

`RECOMMENDED_FEEDS`가 **core의 정적 배열**이다.
[`unregisteredFeeds`](../../packages/core/src/domain/news-feeds.ts#L53)가 이미 등록된 것을 걸러
남은 것만 보여준다 — **다 등록하면 추천 섹션이 사라진다.** 그게 "갱신되지 않는다"의 실체다.

### 만들 것 — 세 단계로 나눈다

**(1) 목록이 마르지 않게 한다 (기반)**

- 주제를 더 넓히고, **추천을 회전시킨다** — 한 번에 전부 보여주지 않고 N개씩,
  볼 때마다 다른 것을. **회전은 결정적으로**(날짜 시드) — 무작위면 새로고침마다 흔들려
  사용자가 방금 본 것을 다시 찾을 수 없다.
  대시보드 동기부여 메시지가 이미 [날짜 기반 결정적 선택](../../apps/web/src/app/%28app%29/page.tsx#L43)을
  쓴다 — **같은 방식.**

**(2) 실제로 살아 있는 피드만 추천한다**

- **`RECOMMENDED_FEEDS`의 원칙을 지킨다**: "여기 넣는 규칙은 **실제로 요청해 확인한 것만** 넣는다"
  (파일 상단 주석). 1차에서 "후보 13개를 실제로 요청해 **파싱되는 8개만** 추가"한 그 방식이다.
- **죽은 추천을 자동으로 내린다.** `FEED_FAIL_THRESHOLD`가 이미 실패를 세고 있다 —
  **그 신호를 추천 목록에도 반영한다**(재구현 금지). 사용자가 추천을 눌렀는데 0건이면
  추천 자체가 신뢰를 잃는다.

**(3) 내가 읽는 것에서 배운다 (선택 — 값이 크다)**

- 사용자가 **읽음 처리한 기사의 피드**를 근거로 비슷한 주제를 올린다.
  `markArticleRead`가 이미 읽음을 기록한다.
- **[확인 필요] 읽음이 서버에 저장되는가.**
  [`readArticles`](../../apps/web/src/lib/readArticles.ts)가 **localStorage일 가능성이 높다**
  (이름과 위치로 볼 때). 그렇다면 기기 간에 공유되지 않고 추천 근거로 약하다.
  **세어 보고 결정한다** — localStorage면 (3)은 다음으로 미룬다.
- **근거를 화면에 밝힌다.** "이 주제를 자주 읽으셨어요" 같은 한 줄.
  근거 없는 추천은 1차 4-5에서 지적받은 "조회수 없는 인기 순위"와 같은 부류다.

### 하지 않을 것

- **외부 추천 API 도입.** 무료 원칙과 충돌하고, 우리 취향 데이터가 밖으로 나간다.
- **LLM으로 추천 목록 생성.** **없는 피드 주소를 그럴듯하게 지어낸다** —
  실제로 요청해 확인한 것만 넣는다는 파일 원칙과 정면 충돌한다.

  같은 core 함수를 쓰므로 자동이다(두 벌로 만들지 않는다).

## 하지 않을 것 (요약)

- **읽을 때마다 번역.** 쿼터가 즉시 소진된다.
- **한국어 기사까지 LLM에 보내기.** 판정은 코드로(HD-003).
- **원문 폐기.** 번역이 이상할 때 대조할 수 없다.
- **`untrustedTextRule` 재구현.** 인벤토리 위반.
