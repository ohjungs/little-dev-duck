## 왜 이 Phase인가 — 무료 티어에 백업이 없다

카탈로그가 지적한 것 중 **가장 조용하고 위험한 사실**:

> **V-010: 백업 (프리 플랜 자동 백업 없음, 수동 덤프 스크립트 필수)**

**지금 이 저장소에 DB 덤프 스크립트가 없다.** 메신저가 생기면 **지울 수 없는 개인 대화**가
쌓이는데, 그것을 잃으면 복구 수단이 없다. `Export/ImportDataButton`은 **사용자가 눌러야** 하고
**브라우저를 거친다** — 운영 백업이 아니다.

> **이 Phase에서 가장 값이 큰 항목은 V-010·V-011·V-012(백업·정기 실행·복구 리허설)다.**
> 카탈로그 등급이 SHOULD인데, **메신저를 만들면 MUST에 가까워진다.**

## T1 — 백업·복구 (V-010~V-012 · V-021)

- **덤프 스크립트 + 정기 실행 + 복구 절차 문서 + 리허설.**
- **[확인 필요] 무료로 어디에 저장하나.** GitHub Actions 아티팩트는 보존 기간이 있고
  **개인 대화를 저장소 근처에 두는 것은 위험하다.** 로컬 다운로드 + 사용자 보관이 현실적이다.
  → **자동화의 한계를 정직하게 적는다.** "정기 백업"이라고 적고 실제로는 안 돌면 최악이다.
- **복구를 실제로 해 본다(리허설).** 이 저장소는 **"실행되지 않은 테스트는 문서다"**를
  [Phase 40](phase_40.md)에서 적었다. **복구해 본 적 없는 백업도 문서다.**
- V-021 데이터 보존 정책 — [Phase 55 T2](phase_55.md)의 콜드 스토리지와 짝.

## T2 — 관측성 (V-005~V-009 · V-018~V-020)

- Realtime 동시 접속·메시지 수(V-005) · 대역폭(V-006) · 에러 로깅(V-007) ·
  Sentry 무료 구간(V-008) · 성능 지표(V-009) · 헬스체크 대시보드(V-018) ·
  상태 페이지(V-019) · 장애 통보(V-020).
- **V-005·V-006이 [Phase 51](phase_51.md)·[55](phase_55.md)의 판단 근거를 만든다.**
  읽음 배치가 실제로 예산을 아끼는지, 썸네일이 대역폭을 줄이는지 **숫자 없이는 알 수 없다.**
  → **측정을 먼저 붙이는 편이 낫다.** 순서를 앞으로 당길 후보다.
- **V-008 Sentry는 확정 스택 밖이다.** 무료 구간이 있어도 **외부로 오류가 나가고
  거기에 메시지 내용이 섞일 수 있다.** → **먼저 `action_log`로 자체 수집**하고,
  부족하면 그때 제안한다(개인정보가 나가는 결정은 사용자 몫이다).
- **V-007 에러 로깅**: `LddError` + `action_log`가 이미 있다 — **새 체계 금지.**

## T3 — 운영 절차 (V-015~V-017 · V-022~V-026)

- 스테이징 분리(V-015) · 피처 플래그 점진 배포(V-016) · 롤백 계획(V-017) ·
  자동 정리 잡(V-022) · 시드·픽스처(V-023) · e2e(V-024) · 단위 테스트(V-025) · 부하 테스트(V-026).
- **V-015 스테이징은 무료 플랜 프로젝트 2개 제한에 걸린다**(카탈로그 실측).
  지금 1개를 쓰고 있으니 1개가 남는다 — **그걸 스테이징으로 쓸지, 두 번째 제품을 위해 남길지가 결정이다.**
- **V-016 피처 플래그는 [Phase 49](phase_49.md)의 `FEATURES` 토글이 이미 그 구조다.** 재사용.
- **V-022 자동 정리 잡** — [Phase 50](phase_50.md)이 만든 **고아 첨부**(업로드는 됐는데 메시지가
  안 만들어진 파일)를 지우는 일이다. Phase 50이 "정리 대상으로 기록"까지만 했으니 **여기서 지운다.**
  **되돌릴 수 없으므로** 먼저 목록을 만들고 개수를 보고한 뒤 실행한다.
- **V-024·V-025는 [Phase 41](phase_41.md)이 e2e를 켠 뒤에 실제로 의미가 있다.**
  메신저 e2e(전송·수신·삭제)는 **두 세션이 필요할 수 있다**(보내는 쪽과 받는 쪽) —
  Playwright의 다중 컨텍스트로 가능한지 실측한다.
- **V-026 부하 테스트는 무료 티어에서 위험하다.** Realtime 200만/월을 테스트로 태울 수 있다.
  → **작은 규모로만, 소비량을 측정하면서.**

## T4 — 인증 강화 (A 19항목)

**[Phase 41](phase_41.md)이 이메일 로그인을 만든 뒤의 후속이다.** 인증 표면이 늘면 이것들이 필요해진다.

| 항목 | 판단 |
|---|---|
| **A-018 비밀번호 변경 시 전 세션 무효화** | **가장 급하다.** 비밀번호가 유출돼 바꿨는데 기존 세션이 살아 있으면 바꾼 의미가 없다 |
| **A-019 계정 잠금(연속 실패 N회)** | [Phase 41 T2](phase_41.md)가 공용 `allowRequest`로 상한을 걸지만 **인스턴스 메모리 한계**가 있다. Supabase Auth 자체 상한이 실제 방어선 — **확인하고 기록한다** |
| A-015·A-016 기기 목록·원격 종료 | A-018과 같은 자리. Supabase Auth가 세션 목록을 주는지 **확인 필요** |
| A-017 새 기기 로그인 알림 | 이메일 발송 → **SMTP 상한**(Phase 41 T3에서 조사한 그 한계) |
| A-020 로그인 이력 감사 로그 | `action_log`에 담는다. **새 테이블 금지** |
| A-011 탈퇴 유예 30일 | [Phase 35](phase_35.md)가 만든 계정 삭제는 **즉시·되돌릴 수 없다.** 유예를 넣으면 그 계약이 바뀐다 — **신중하게. 지금 것이 더 안전할 수 있다** |
| A-013·A-014 TOTP·백업 코드 | 개인용에 과할 수 있으나 저비용 |
| A-021 매직 링크 · A-022 패스키 | **패스키가 비밀번호보다 안전하다.** Phase 41 이후 검토 가치 있음 |
| A-023·A-024 앱 잠금(PIN·생체) | 데스크톱 위젯이 항상 켜져 있으므로 **실제 값이 있다** |
| A-029 이메일 변경 | `profiles.email`과 `auth.users` 양쪽이다 — **동기화를 틀리면 로그인이 깨진다** |
| A-030·A-031 약관 동의 버전 관리·철회 | 공개 배포된 앱이라 필요. `U-027`(처리방침)과 짝 |
| A-010 계정 삭제 | **이미 있다**([Phase 35](phase_35.md)) — 다만 **꺼져 있다.** `SUPABASE_SERVICE_ROLE_KEY` 대기 |
| A-012 SMS 인증 | 비용. **하지 않는다** |
| A-028 계정 이관 | [Phase 55](phase_55.md)의 내보내기·가져오기로 갈음 |

## T5 — 보안 심화 (U 13항목 · K-027)

- CSRF 확인(U-012) · 감사 로그(U-015) · **민감 정보 자동 감지(U-016)** · 스포일러 마스킹(U-017) ·
  비밀 대화(U-018) · 방 잠금 PIN(U-019) · 자동 삭제 메시지(U-020) · 스크린샷 방지 시도(U-021) ·
  처리방침(U-027) · 외부 전송 고지(U-028) · 보관 기간(U-029) · 파기 자동화(U-030) ·
  침해 대응 문서(U-033) · 파일 바이러스 검사(K-027) · 중복 전송 정책(B-015).
- **U-012 CSRF는 이미 조사돼 있다** — `@supabase/ssr`이 인증 쿠키를 `sameSite: "lax"`로 굽고,
  그래서 크로스사이트 POST에 쿠키가 안 실린다([Phase 36](phase_36.md) 실측).
  **메시지 전송 라우트에도 같은 근거가 적용되는지 확인하고 주석에 남긴다** — 재조사 금지.
- **U-016 민감 정보 감지(계좌번호·토큰)**: 판정은 **결정적 — 정규식으로**(HD-003).
  **다만 과하게 잡으면 정상 메시지를 막는다** — [Phase 37](../Status.md)이 오류 문구를
  "좁게만 잡는다"로 처리한 판단과 같다. **경고만 하고 막지 않는다.**
- **U-021 스크린샷 방지는 우회 가능하다.** 카탈로그가 "우회 가능함을 명시"라고 적은 게 맞다 —
  **할 수 있는 것처럼 만들지 않는다.** J-018(스크린샷 감지 알림)은 SKIP이 정확하다.
- **U-030 파기 자동화**: `delete_all_my_data` + `schemaGuard`의 `purgeMissing`이 **이미 그 구조다.**
  메신저 테이블이 거기 들어가는지 **Phase 50이 이미 검사받는다.** 재구현 금지.
- **K-027 바이러스 검사는 외부 API 비용**이다. → **파일 타입 화이트리스트**(Phase 50 K-028)로
  대부분 막는다. 그 한계를 적는다.

## 의존 계약

- **마이그레이션 1~2건**(감사 로그 확장 · 약관 동의 버전). down 포함.
- **신규 의존성 0개.** Sentry·바이러스 검사는 **도입하지 않는 쪽으로 시작.**
- **[사용자 실행 필요]** `CRON_SECRET` · `SUPABASE_SERVICE_ROLE_KEY` · 마이그레이션 적용 ·
  스테이징 프로젝트 사용 여부 결정.
- **[Phase 41 선행]** T4 전체가 이메일 로그인 이후의 문제다.

## 하지 않을 것

- **새 에러 로깅·감사 로그 테이블.** `LddError` + `action_log`가 있다.
- **Sentry를 조용히 도입.** 메시지 내용이 외부로 나갈 수 있다 — 사용자 결정.
- **CSRF 재조사.** Phase 36이 실측해 뒀다.
- **스크린샷 방지를 할 수 있는 것처럼 만들기.**
- **민감 정보 감지로 전송을 막기.** 정상 메시지가 막힌다 — 경고만.
- **복구해 본 적 없는 백업을 "백업 있음"으로 적기.**
- **부하 테스트로 Realtime 예산 태우기.**
- **`purgeMissing`·파기 함수 재구현.** 있다.
