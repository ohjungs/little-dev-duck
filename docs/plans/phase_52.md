## 왜 이 Phase가 메신저의 존재 이유인가

카탈로그 R 섹션 머리말이 정확하다: **"이 카테고리가 LDD에서 메신저를 만들 실제 명분이다."**

혼자 쓰는 메신저는 그 자체로 값이 크지 않다. **값은 여기서 나온다** —
채팅이 **워크스페이스를 조작하는 입구**가 되는 것.

**그리고 이 Phase는 대부분 이미 있는 것을 잇는 일이다.**

| 카탈로그 항목 | 이미 있는 것 |
|---|---|
| R-001~R-003 오리 1:1 + LLM + 컨텍스트 | ✅ `DuckChatPanel` |
| R-011 RAG (pgvector) | ✅ 페이지 저장 시 재색인 |
| R-016~R-018 툴 호출 + 승인 카드 + 파괴적 작업 승인 강제 | ✅ [Phase 30 T2](phase_30.md) |
| R-009 쿼터 관리 | ✅ 공용 `allowRequest`(7 라우트) |
| S-012 GitHub 이슈 | ✅ `GitHubIssuesLink` |
| S-015 Gmail | ✅ `GmailLink` |
| S-018 Google Calendar | ✅ `GoogleCalendarLink` |
| I-028·I-029 할 일·일정 변환 | 🟡 오리 도구가 이미 생성한다 — **메시지에서 변환하는 입구만 없다** |

## T1 — 메시지 ↔ 워크스페이스 변환 (S-001·S-003 · I-028·I-029·I-030)

- 메시지 컨텍스트 메뉴에 **할 일로 · 일정으로 · 노트로**.
- **생성 로직을 재구현하지 않는다.** [Phase 30 T2](phase_30.md)의 오리 도구가
  이미 할 일·일정을 만든다. **그 함수를 부른다.**
- **되돌리기 어려운 것에는 승인을 강제한다** — Phase 30이 세운 계약. 생성은 되돌릴 수 있어
  승인 카드가 과하지만, **노트로 저장은 문서를 바꾸므로** 다르다. 항목별로 판단해 적는다.
- 변환 후 **원본 메시지에 표시**한다("할 일로 만들었어요" + 링크). 안 하면 같은 메시지를 두 번 변환한다.

## T2 — 슬래시 커맨드 (F-020·F-021 · S-025)

- `/할일` · `/일정` · `/요약` · `/오늘` · `/주간`.
- **자동완성 팝업**(F-021). 커맨드가 있는지 모르면 아무도 안 쓴다.
- **판정은 결정적으로 — 코드가 한다**(HD-003). 커맨드 파싱을 LLM에 맡기면
  **쿼터를 태우고 결과가 불안정하다.** 파싱은 정규식, LLM은 자유 텍스트 해석에만.
- **`CommandPalette`(Cmd+K)와 겹치지 않게 한다.** 그건 이미 있다 —
  **같은 동작을 두 입구가 다르게 하면 안 된다.** 공용 액션 정의를 하나 두고 둘이 쓴다.

## T3 — 알림 카드 인입 (H-016·H-017·H-025·H-027 · S-002·S-004·S-005·S-013·S-014)

- 할 일 카드 · 일정 카드 · **알림 카드**(CI 실패·배포 완료) · **승인 요청 카드**.
- **⚠ H-027 승인 요청 카드는 이미 있다** — `DuckChatPanel`의 `pendingApproval`.
  **그 컴포넌트를 방 안으로 가져온다.** 새로 만들면 승인 UI가 두 벌이 되고,
  **파괴적 작업 승인이 한쪽에서만 강제되는 최악의 상태**가 된다.
- **웹훅 수신(S-022·S-023)은 이 Phase의 가장 위험한 부분이다.**
  - **서명 검증 없는 웹훅은 누구나 우리 채팅에 메시지를 넣는 통로다.**
    S-023(서명 검증)을 **선택이 아니라 필수로** 올린다.
  - 이 저장소에 전례가 있다: `/api/keepalive`가 `CRON_SECRET` 없이 배포돼
    **누구나 호출할 수 있는 상태**로 남았다([PENDING.md](../loop-eng/PENDING.md) 6번).
    **같은 실수를 반복하지 않는다** — 시크릿이 없으면 **엔드포인트가 아예 동작하지 않게** 한다
    (있으면 검사하는 방식은 미설정 시 열린다).
  - **인젝션**: 웹훅 본문은 **외부 텍스트**다. 그게 LLM 요약에 들어가면
    [Phase 32](phase_32.md)가 막은 그 경로다. `untrustedTextRule`을 쓴다 — **재구현 금지.**
  - **SSRF**(U-008): 링크 미리보기(H-010)를 만들면 **우리 서버가 임의 URL을 가져온다.**
    내부망 차단이 필요하다. [Phase 41 이전에 이미 SSRF 2건을 Next.js 패치로 막았다](../Status.md) —
    우리가 새로 만들지 않는다.

## T4 — RAG 확장: 대화를 기억으로 (R-012·R-013 · L-013·L-014)

- **참조 출처 표시**(R-012)를 먼저 한다. 어디서 온 답인지 모르면 검증할 수 없다.
- **대화 임베딩**(R-013)은 신중하게:
  - 메시지마다 임베딩하면 **DB 500MB를 벡터가 먹는다.**
  - **[확인 필요] 지금 `ai_embeddings`가 얼마나 쓰고 있는가.** 세어 보고 결정한다.
  - **[추정] 요약 단위로 임베딩하는 것이 맞다** — 메시지 단위는 짧아 검색 품질도 낮다.
- **기억 삭제·토글**(R-014·R-015)을 함께 만든다.
  지울 수 없는 기억은 **개인정보 문제**이고, `delete_all_my_data`에도 들어가야 한다
  (`schemaGuard`가 검사한다).

## T5 — 브리핑 (R-025·R-027 · J-011)

- 아침 요약 · 미확인 메시지 요약.
- **[Phase 45](phase_45.md)·[47](phase_47.md)과 쿼터를 공유한다.**
  자율 발화(45) · 뉴스 번역(47) · 브리핑(52)이 **같은 무료 쿼터**를 먹는다.
  **Phase 45가 예산을 확정하고 이 Phase가 배분받는다.** 따로 만들면 합쳐서 초과한다.
- **주기 실행이 필요하다.** Vercel Cron이 이미 `/api/keepalive`를 부른다 —
  **그 방식을 쓴다.** 새 스케줄러를 만들지 않는다.
- 이미 있는 것: [`WeeklyDigestTrigger`](../../apps/web/src/components/WeeklyDigestTrigger.tsx) ·
  스탠드업 생성([Phase 46 T4](phase_46.md)에서 이름을 고친다).
  **셋이 같은 일을 다르게 하지 않게 정리한다.**

## 하지 않을 것

- **승인 카드 두 벌.** 파괴적 작업 승인이 한쪽에서만 강제되는 최악을 만든다.
- **서명 검증 없는 웹훅.** 누구나 우리 채팅에 글을 넣는다.
- **시크릿 없으면 열리는 엔드포인트.** keepalive의 실수를 반복한다.
- **커맨드 파싱을 LLM에.** 결정적 작업은 코드로(HD-003).
- **메시지 단위 임베딩.** DB 500MB를 벡터가 먹는다.
- **새 스케줄러.** Vercel Cron이 이미 있다.
- **`untrustedTextRule` 재구현.** 인벤토리 위반.
