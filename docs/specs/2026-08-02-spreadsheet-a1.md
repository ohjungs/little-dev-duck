## 1. 목표·배경

사용자 요청 2-6("페이지 안에 엑셀 기능")을 이 저장소는 **열 집계**(합계·평균·개수)로 해석해
Phase 33을 만들었다. 2026-07-31에 사용자가 정정했다 — **MS Office의 엑셀**, 즉 셀 주소(A1)로
서로를 참조하고 수식이 자동 재계산되는 진짜 스프레드시트다. 2026-08-02에 착수가 결정됐다(C-1).

### 왜 기존 데이터베이스 뷰로는 안 되나

현재 데이터베이스는 **레코드 모델**이다(`packages/core/src/domain/database-view.ts`):
데이터베이스 = `db_schema`가 설정된 페이지, **행 = 그 페이지의 자식 페이지**, 값 =
`pages.row_props` jsonb. 열은 이름과 타입을 가진 속성이고, 셀은 "그 행의 그 속성값"이다.

스프레드시트는 **격자 모델**이다. 셀은 좌표(A1)로 식별되고, 타입은 열이 아니라 셀마다 다르며,
셀이 다른 셀을 참조해 값을 만든다. 이 둘은 표처럼 보일 뿐 다른 자료구조다:

| | 데이터베이스 뷰 | 스프레드시트 |
|---|---|---|
| 셀 식별 | (행 페이지 id, 속성 id) | (시트, 행 번호, 열 번호) |
| 타입 | 열 단위 | 셀 단위 |
| 빈 셀 | 속성 미설정 | 좌표는 항상 존재 |
| 계산 | 열 집계 1단계 | 셀 → 셀 임의 깊이, 순환 검출 필요 |
| 행 삽입 | 자식 페이지 추가 | 아래 모든 참조가 따라 이동 |

즉 기존 코드를 고쳐 쓰는 길이 없다. **새 문서 종류를 추가한다.**

### "MS Office급"의 범위를 여기서 정한다

엑셀 완전 호환은 목표가 아니다(피벗 테이블, VBA, 파워쿼리, 조건부 서식 규칙 엔진, 배열 수식의
암시적 교차 등은 각각이 이 제품만 한 크기다). 이 스펙이 약속하는 "엑셀급"은 셋이다:

1. **셀 주소와 수식** — `=A1+B2*2`, `=SUM(A1:A10)`, `$A$1` 절대참조, `Sheet2!A1` 시트 간 참조,
   순환 참조 검출, 의존 셀만 골라 재계산.
2. **엑셀과 데이터가 오간다** — `.xlsx` 가져오기·내보내기, 엑셀에서 복사한 것을 붙여넣기(TSV),
   CSV. 이게 없으면 "엑셀급"이라는 말이 실질을 갖지 못한다.
3. **엑셀처럼 조작된다** — 범위 선택, 채우기 핸들, 복사·붙여넣기, 실행취소, 열 너비, 틀 고정,
   숫자 서식, 정렬·필터.

## 2. 설계 결정

### D-1. 저장: 셀 전용 테이블 (`sheets` + `sheet_cells`) — 2026-08-02 사용자 결정

초안은 `pages.sheet_data` jsonb를 권했으나 **사용자가 셀 전용 테이블을 골랐고, 재검토 결과
그쪽이 맞다.** 이 스펙이 약속한 "엑셀급"과 jsonb 한 덩어리는 서로 어긋난다:

- **한 글자 고칠 때마다 문서 전체를 다시 쓴다.** 2만 셀이면 매 편집이 1MB 왕복이다.
  엑셀처럼 쓰는 도구에서 이건 타이핑 지연으로 바로 드러난다.
- **상한 자체가 약속과 모순이다.** "엑셀급"이라 해 놓고 2만 셀에서 저장을 거부하는 것은
  이 스펙이 스스로 어긴 약속이 된다.
- 두 사람이 같은 문서를 열면 나중 저장이 앞선 저장을 통째로 덮는다(셀 단위면 충돌 면적이 셀뿐).

```
sheets                                   -- 시트 = 페이지의 자식 (탭 하나)
  id uuid pk
  page_id uuid -> pages(id) on delete cascade
  user_id uuid -> auth.users(id) on delete cascade   -- RLS 단순화(조인 없이 판정)
  name text, position int
  meta jsonb    -- 열 너비·행 높이·틀 고정·병합·이름정의·서식 팔레트 (셀에 비해 작다)

sheet_cells                              -- 비어 있지 않은 셀만 (희소)
  sheet_id uuid -> sheets(id) on delete cascade
  user_id uuid -> auth.users(id) on delete cascade
  r int, c int                           -- 0-based
  v jsonb        -- 입력된 값 (문자열|숫자|불리언|null)
  f text         -- 수식 원문 ('=' 포함, 없으면 null)
  s int          -- meta.styles 인덱스
  primary key (sheet_id, r, c)
```

`user_id`를 두 테이블에 **비정규화**한다. RLS 정책이 조인 없이 `user_id = auth.uid()`로
끝나 정책이 단순해지고(이 저장소가 이미 쓰는 형태), 셀 대량 조회에서 조인 비용이 사라진다.
대신 `page_id`와 `user_id`가 어긋날 수 있으므로 **삽입 시 소유자 일치를 트리거로 강제**한다
(`room_id_immutable`이 세운 선례와 같은 수법).

계산 결과는 저장하지 않는다(`v`와 `f`만). 저장하면 반드시 실제 값과 어긋나는 순간이 생기고
(다른 기기에서 편집·함수 구현 변경), 그 어긋남은 "틀린 숫자가 맞는 것처럼 보이는" 형태로
나타난다. 불러올 때 계산한다.

### D-1-a. 이 선택이 **추가로 만드는 일** (정직하게)

jsonb였으면 공짜였을 것들을 직접 배선해야 한다. 빠뜨리면 조용히 깨지는 것들이라 전부 AC로 넣는다:

| 잃는 것 | 대응 | 안 하면 |
|---|---|---|
| `delete_all_my_data` | 함수에 두 테이블 추가 | **계정 삭제가 통째로 실패**(메신저 제거 때 실제로 겪은 모양) |
| 백업 내보내기·가져오기 | 스키마 v6에 시트 추가 | 백업이 시트를 빼먹고, 사용자는 그걸 모른다 |
| 휴지통·영구삭제 | `on delete cascade` + 휴지통은 페이지 플래그 그대로 | 고아 셀이 남는다 |
| 버전 기록(`page_versions`) | **1차 범위에서 제외**(T8에서 재검토) | 시트에는 실행취소만 있고 기록은 없다 — 명시한다 |
| 공개 공유 | 공개 페이지가 시트면 셀도 anon 읽기 허용 정책 필요 | 공유 링크에서 빈 표가 보인다 |
| 검색·RAG | 시트 요약 텍스트를 `pages.plain_text`에 파생 저장 | 오리가 시트 내용을 모른다 |

행·열 삽입은 `update sheet_cells set r = r + 1 where sheet_id = ? and r >= ?` 한 문장으로
원자적으로 처리한다(jsonb였다면 전체 재작성). 이건 오히려 셀 테이블이 유리한 지점이다.

**상한**: 시트당 셀 100만, 문서당 시트 50. 무료 티어 500MB 기준 셀 1개 약 100바이트로
100만 셀 ≈ 100MB — 한 문서가 DB를 다 먹지 않도록 계정 전체 셀 수에도 상한을 둔다.

### D-2. 수식 엔진은 `packages/core`에 의존성 없이 직접 만든다

토크나이저 → 파서(우선순위 등반) → 평가기 → 의존성 그래프 → 위상 재계산. 전부 순수 함수라
STDD로 덮기 좋고, `core`는 아무것도 import하지 않는다는 규칙(CLAUDE.md 3-5)과 맞는다.

기성 라이브러리(HyperFormula 등)를 쓰지 않는 이유: 번들이 크고(수백 KB), 라이선스가 GPL/상용
이중이며, 오류 문구·한국어 함수명 같은 세부를 우리가 못 정한다. 반대로 직접 만들면 **엑셀과
다르게 동작하는 지점을 우리가 알고 고를 수 있다**(아래 D-4).

### D-3. 계산 모델

- **참조**: `A1` · `$A$1`/`A$1`/`$A1` · `A1:B10` · `Sheet2!A1` · 이름 정의(`매출`)
- **연산자**: `+ - * / ^ %` · 비교 `= <> < > <= >=` · 문자열 결합 `&` · 단항 `-`/`+`
- **오류값**: `#DIV/0!` `#VALUE!` `#REF!` `#NAME?` `#N/A` `#NUM!` — 엑셀과 같은 표기.
  오류는 전파된다(오류를 참조한 셀도 그 오류가 된다), `IFERROR`로만 잡는다.
- **재계산**: 셀을 고치면 그 셀에 의존하는 셀만 역방향 그래프로 모아 위상순으로 다시 센다.
  전체 재계산은 문서를 열 때 한 번.
- **휘발성 함수**(`TODAY` `NOW` `RAND` `RANDBETWEEN`)는 매 재계산마다 다시 센다.

### D-4. 엑셀과 **일부러 다르게** 하는 것

정직하게 미리 적는다. 나중에 "왜 다르지"로 다시 조사하지 않기 위해서다.

- **순환 참조**: 엑셀은 경고 대화상자를 띄우고 0을 넣는다. 우리는 그 셀에 `#CIRCULAR!`를
  표시한다. 이유 — 0은 계산에 섞여 들어가 **틀린 결과를 조용히 만들고**, 개인 도구에서는
  경고 대화상자를 놓치기 쉽다. 순환은 값이 아니라 오류로 다룬다.
- **날짜의 내부 표현**: 엑셀은 1900년 기준 일련번호(그리고 1900년 윤년 버그를 호환성 때문에
  유지한다). 우리는 `YYYY-MM-DD` 문자열로 저장하고 날짜 함수가 해석한다. 기존 코드가 이미
  그 형식을 쓰고(`database-view.ts`의 date 속성) KST 처리도 그쪽에 있다. `.xlsx` 입출력에서만
  일련번호로 변환한다.
- **한국어 함수명은 지원하지 않는다.** 영문 함수명만 받는다(엑셀 한국어판은 `SUM`을
  `SUM`으로 쓰므로 실질 차이는 거의 없다).

### D-5. 화면

가상 스크롤 격자를 **직접 구현**한다(`react-window` 같은 의존성 추가 없이). 스프레드시트는
행·열이 모두 가변 크기이고 고정 헤더·틀 고정·병합 셀이 있어 범용 가상 리스트가 그대로 맞지
않는다. 이 저장소에는 이미 Canvas 격자(픽셀 오피스)와 `ResizeObserver` 사용 선례가 있다.

DOM으로 그린다(Canvas 아님). 셀 편집·접근성·한글 IME·복사 붙여넣기가 DOM에서 훨씬 정확하다.
보이는 범위 + 여유분만 렌더한다.

## 3. 수용 기준 (Acceptance Criteria)

### 계약·저장

- **AC-1**: `sheets`·`sheet_cells` 테이블 마이그레이션과 짝이 되는 down 스크립트가 있다.
  RLS가 두 테이블에 켜져 있고 정책이 `user_id = (select auth.uid())`다. 시트가 없는 기존
  페이지의 동작은 한 글자도 바뀌지 않는다(회귀 테스트로 잠근다).
- **AC-2**: `sheets.page_id`가 가리키는 페이지의 소유자와 `sheets.user_id`가 다르면 INSERT/UPDATE가
  거부된다(트리거). `sheet_cells.user_id`도 그 시트의 소유자와 같아야 한다.
- **AC-3**: 상한이 강제된다 — 시트당 셀 100만 · 문서당 시트 50 · 계정 전체 셀 수 상한.
  넘는 저장은 거부되고 사용자에게 사유가 보인다(조용히 잘리지 않는다).
- **AC-3a**: `delete_all_my_data`가 `sheets`·`sheet_cells`를 지운다. **계정 삭제 경로 전체가
  성공한다**(pgTAP으로 잠근다 — 메신저 제거 때 이 함수가 없는 테이블을 지우려다 계정 삭제를
  통째로 깨뜨린 전례가 있다).
- **AC-3b**: 백업 내보내기·가져오기가 시트를 포함한다(스키마 v6). 옛 백업 파일(시트 키 없음)도
  그대로 읽힌다.
- **AC-3c**: 페이지를 영구 삭제하면 그 시트와 셀이 함께 사라진다(cascade). 고아 행 0건을
  pgTAP이 확인한다.
- **AC-3d**: 공개 공유된 페이지가 시트면 anon이 셀을 읽을 수 있다. 공개가 아니면 못 읽는다.

### 수식 엔진

- **AC-4**: `=A1+B2*2`가 우선순위대로 계산된다. 괄호·단항 부호·거듭제곱 결합(우결합)까지.
- **AC-5**: `A1` 상대참조, `$A$1`/`A$1`/`$A1` 혼합참조를 파싱하고, **복사·붙여넣기와 채우기
  핸들에서 상대참조만 이동한다.**
- **AC-6**: `=SUM(A1:A10)` 범위 참조가 동작하고, 범위 안의 빈 셀은 0이 아니라 **건너뛴다**
  (`AVERAGE`의 분모에 들어가지 않는다 — 엑셀과 같다).
- **AC-7**: `=Sheet2!A1` 시트 간 참조가 동작한다. 없는 시트는 `#REF!`.
- **AC-8**: 순환 참조는 `#CIRCULAR!`로 표시되고, **그 셀만** 오류가 된다(무한 루프·스택 오버플로
  없음). 자기 자신 참조(`A1`에 `=A1`)와 3개 이상이 도는 경우 모두.
- **AC-9**: 오류가 전파된다 — `=A1+1`에서 A1이 `#DIV/0!`이면 결과도 `#DIV/0!`.
  `=IFERROR(A1+1, 0)`은 0.
- **AC-10**: 셀 하나를 고치면 **그 셀에 의존하는 셀만** 다시 계산된다(의존하지 않는 셀의 계산
  함수가 호출되지 않음을 단언한다 — "전체를 다시 세도 결과는 같다"로 통과하지 않게).
- **AC-11**: 1차 함수 목록(아래 4절 T4)이 전부 구현되고, 각 함수마다 정상·경계·오류 입력
  테스트가 있다.

### 표 조작

- **AC-12**: 행·열 삽입/삭제 시 **수식의 참조가 따라 이동한다.** 삭제된 셀을 가리키던 참조는
  `#REF!`가 된다(참조가 조용히 옆 셀을 가리키지 않는다).
- **AC-13**: 엑셀에서 복사한 범위를 붙여넣으면 표로 들어온다(TSV 파싱, 줄바꿈·따옴표 포함 셀
  처리). 반대로 우리에서 복사한 것이 엑셀에 붙는다.
- **AC-14**: 채우기 핸들로 끌면 값·수식·연속 데이터(1,2,3… / 월,화,수…)가 채워진다.
- **AC-15**: 실행취소·다시실행이 셀 편집·붙여넣기·행열 삽입삭제·서식에 모두 적용된다.

### 상호운용

- **AC-16**: `.xlsx` 파일을 가져오면 값·수식·시트 구성·기본 서식이 들어온다. 우리가 모르는
  기능(피벗·매크로 등)은 **값으로 떨어뜨리고 무엇을 잃었는지 알린다**(조용히 버리지 않는다).
- **AC-17**: `.xlsx`로 내보내면 엑셀에서 열린다. 수식은 수식으로, 계산된 값도 함께 실린다.
- **AC-18**: CSV 가져오기·내보내기(UTF-8 BOM — 엑셀 한글 깨짐 방지).

### 화면·접근성

- **AC-19**: 10,000셀 문서에서 스크롤이 끊기지 않는다(보이는 범위만 렌더).
- **AC-20**: 키보드만으로 이동·편집·범위 선택이 된다(방향키·Tab·Enter·Shift+방향·Ctrl+방향·

- **AC-21**: 한글 IME 조합 중 Enter가 셀 확정으로 새지 않는다(조합 완료와 확정을 구분).
- **AC-22**: 기능 토글에서 끌 수 있다(새 기능 키 `sheet`). 끄면 화면·API 양쪽이 막힌다.

## 5. E2E 시나리오 (Given/When/Then)

- **E1 수식이 산다**: 새 시트 페이지 → A1에 `10`, A2에 `20`, A3에 `=SUM(A1:A2)` →
  A3에 `30`이 보인다 → A1을 `15`로 고치면 **A3이 `35`로 바뀐다** → 새로고침해도 `35`.
- **E2 참조가 따라간다**: A3의 `=SUM(A1:A2)`를 B3에 붙여넣으면 B3의 수식이 `=SUM(B1:B2)`다
  (수식 입력줄에서 확인).
- **E3 순환**: A1에 `=A1` → A1에 `#CIRCULAR!`가 보이고 **화면이 멈추지 않는다**(다른 셀 편집 가능).
- **E4 엑셀에서 붙여넣기**: 클립보드에 TSV(줄바꿈 포함 셀 1개 포함)를 넣고 A1에서 붙여넣기 →
  격자가 그 모양대로 채워진다.
- **E5 내보내고 다시 넣기**: 수식이 있는 시트를 `.xlsx`로 내보낸 뒤 그 파일을 다시 가져오면
  값과 수식이 보존된다(왕복).
- **E6 키보드만으로**: Tab으로 격자 진입 → 방향키 이동 → F2 편집 → Esc 취소 →
  Shift+방향키로 범위 선택 → Ctrl+C/Ctrl+V.
- **E7 기능 토글**: 관리자가 `sheet`를 끄면 시트 페이지가 안내 화면으로 바뀌고 API가 403.

## 8. 기존 Phase 33(열 집계)을 어떻게 하나

**없애지 않기를 권한다.** 데이터베이스 뷰의 열 집계는 레코드 모델의 기능이고(칸반·필터·정렬과
한 덩어리), 스프레드시트는 그것과 다른 도구다. 노션도 데이터베이스와 별개로 표를 갖는다.
없애면 지금 칸반·보드를 쓰는 경로가 함께 상한다.

앞서 "Phase 33을 버리게 된다"고 적었던 것은 **과했다** — 사용자가 말한 것은 "지금 것으로는
부족하다"이지 "지금 것을 없애라"가 아니었다. 정정한다.

## 9. 규모와 순서에 대한 정직한 말

T1~T9는 **최소 10~13 사이클**이다(셀 테이블 선택으로 D-1-a의 배선이 1~2 사이클 늘었다).
이 저장소가 지금까지 한 어떤 작업보다 크다.

사용자 결정(Q5)에 따라 **T4에서 멈추지 않고 T9까지 이어서 진행한다.** 다만 T 하나가 끝날 때마다
검증 결과를 보고한다 — 멈추지 않는 것과 말없이 가는 것은 다르다.

먼저 만들 화면이 없어 답답할 수 있다(T1~T4는 엔진뿐이다). 그러나 반대 순서(화면 먼저)는 이
부류에서 반드시 다시 짓게 된다 — 격자 UI는 엔진의 계산 순서·오류 표현·참조 이동 규칙을 그대로
드러내는 껍데기라, 엔진이 흔들리면 화면도 같이 흔들린다.

**다른 대형 2건(슬라이드 편집기·다국어)과의 관계**: 사용자가 "그 외 다른 것도 진행"이라고
했으므로 두 스펙도 쓴다. 다만 **구현은 순차로 간다** — CLAUDE.md 3-3이 병렬을 worktree 분리
2~3개로 제한하고, 세 기능 모두 `pages`·에디터·전역 문자열이라는 같은 표면을 건드려 동시에
고치면 서로를 깨뜨린다. 스프레드시트를 주 트랙으로 두고, 나머지는 스펙을 먼저 완성해 둔다.
