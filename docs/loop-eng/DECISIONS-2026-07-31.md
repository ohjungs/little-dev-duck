### A-3 상세 — 적용 결과 (2026-07-31)

사용자가 Supabase access token 발급 화면까지 갔지만 **토큰은 필요하지 않았다** — claude.ai
Supabase 커넥터가 연결돼 있어 그 경로로 직접 적용했다(2026-07-30 선례와 같다).

적용 전 조회로 **`message_sender_immutable`이 실제로 미적용**임을 확인했다(원격 목록이
`room_id_immutable`에서 끝나 있었다 — 인수인계 문서의 "미적용 확인"이 사실이었다).

| 마이그레이션 | 결과 |
|---|---|
| `message_sender_immutable` | 적용. 트리거 `messages_guard_sender` 생성 |
| `message_attachment_delete_owner` | 적용. 삭제 정책이 `owner = auth.uid()` + 방 멤버로 좁혀짐 |

**"적용됐다"에서 멈추지 않고 실측했다.** 실제 UPDATE로 위조를 시도해 전부 되돌아가는
트랜잭션 안에서 확인했다:

- `sender_type`을 'agent'로 위조 → **차단**("sender_type은 변경할 수 없어요.")
- `sender_user_id`를 남의 것으로 위조 → **차단**("sender_user_id는 변경할 수 없어요.")
- 정상 경로(본문 수정 + `edited_at`) → **통과**. 기능 손실 0 확인.
- 첨부 정책 실물 조회: DELETE는 `owner = auth.uid()`로 좁혀졌고, SELECT·INSERT는
  방 멤버 그대로(같은 방 사람은 서로의 이미지를 봐야 한다).
- `owner`가 비어 있어 아무도 못 지우게 되는 행: **0건**(버킷에 객체 자체가 0건).
- 어드바이저 재실행: **ERROR 0건.** 새 트리거 함수는 목록에 없다 — SECURITY DEFINER로
  만들지 않은 선택이 노출 표면을 늘리지 않았음을 어드바이저가 확인해 줬다.

**메신저를 지우기로 한 것(B-9)과의 관계**: 어차피 지울 테이블에 자물쇠를 다는 셈이지만,
제거는 여러 단계라 그때까지 구멍이 열려 있다. 테이블을 내리면 이 트리거·정책도 함께 사라진다.

## 이 결정들이 만드는 작업

**작은 것 (결정만으로 바로 됨)**

- B-5 취약점 강제: `pnpm.overrides`에 postcss·sharp·brace-expansion. **린트·이미지 처리가 깨질
  수 있고, 깨지면 되돌린다**는 것을 사용자가 알고 고른 선택지다.
- B-8: 캘린더 삭제 미지원 확정 → mv 112번의 결정 대기 해제.
- B-10: Status → History 이관 + 자동화.

**중간**

- B-4 계정 삭제: 코드는 이미 배포돼 있고 **환경변수 하나로 켜진다**
  (`SUPABASE_SERVICE_ROLE_KEY`). "본인 계정만"은 이미 코드가 그렇게 돼 있다 — 라우트가 요청
  본문을 아예 읽지 않고 세션에서 꺼낸 본인만 지운다. **사용자가 Vercel에 키를 넣어야 한다.**
- B-6 기사 이미지: `articles.image_url` 컬럼(마이그레이션) + RSS enclosure·media:content 추출.
  생성형 폴백은 Gemini 무료 티어 이미지 생성 가능 여부를 먼저 확인해야 한다 —
  **[미검증]** 확인 전에는 "이미지 없으면 지금처럼 텍스트 카드"가 폴백이다.
- B-7 메일 확인: 스위치 자체는 **사용자가 Supabase 대시보드에서** 켠다. 켜면 가입 흐름에
  "메일함을 확인하세요" 상태가 생기므로 화면·문구·테스트가 따라와야 한다.
- B-9 메신저 제거: 되돌리기 어려운 삭제라 **범위를 먼저 확정해야 한다**(아래).

**큰 것 — 사실상 새 제품 단위**

- B-2 A1 스프레드시트: 현재 데이터베이스 모델(행=레코드, 열=속성)과 **다른 모델**이다.
  수식 파서·셀 참조·재계산 그래프가 필요하다. 기존 Phase 33(열 집계)은 버리게 된다.

## B-9(메신저 제거)에서 확인이 필요한 것

"없애도 된다"의 범위가 셋으로 갈린다. 되돌리기 어려운 쪽부터:

1. **입구만 닫기** — 사이드바·명령 팔레트에서 메신저를 빼고 라우트를 남긴다. 되돌리기 쉽다.
2. **화면·라우트 삭제** — `/messages` 관련 컴포넌트·API를 지운다. DB는 남는다(데이터 보존).
3. **DB까지 삭제** — rooms·messages·room_members·첨부 버킷까지 내린다. **대화 기록이 사라진다.**

지금 오리 대화는 대시보드 패널과 메신저 오리 방 **양쪽**에 있고, 오리 방에만 있는 것이
멀티턴 맥락·이어 말하기다. 2·3을 고르면 그 경로를 대시보드 패널로 옮기는 작업이 함께 필요하다.
