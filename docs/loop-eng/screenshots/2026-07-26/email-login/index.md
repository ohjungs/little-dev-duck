  고친 뒤 재빌드·재촬영해 확인했다.

## 배치 판단 (근거)

- **OAuth를 위에, 이메일을 아래에.** 기존 사용자는 전부 OAuth로 가입했다 — 이메일 폼을 위에
  놓으면 그 사람들이 "내 계정이 없어졌나" 하고 헷갈린다.
- **다크 팔레트를 그대로 따랐다.** 이 카드의 색은 오프닝 영상 배경(#070705)에 맞춘 것이고
  그 이유가 코드 주석에 적혀 있다. 테마 토큰을 쓰면 다크 모드에서 이음선이 다시 생긴다 —
  새 미감을 발명하는 대신 문서화된 결정을 따랐다.
- **별 화면을 만들지 않고 한 폼에서 탭으로.** 라우트를 늘리면 `/login`에서 두 번 밟은
  정적 프리렌더 + CSP 함정을 다시 밟는다.

## 아직 못 본 것 (정직하게)

- **이메일 로그인의 실제 동작.** Supabase 대시보드에서 Email provider를 켜기 전이라
  지금 폼을 제출하면 "이메일 로그인이 아직 준비되지 않았습니다. Google 또는 GitHub로
  계속해 주세요."가 뜬다 — **그게 의도된 동작이다**(정체 모를 실패로 두지 않았다).
- **가입 → 메일 확인 → 로그인 전체 흐름.** provider가 켜져야 재현된다.
- **오류 문구가 화면에 뜨는 모습**(error·notice 상태). 실패를 유발해야 나타나므로
  provider가 켜진 뒤에 봐야 한다. 문구 판정 자체는 core 테스트 10건으로 잠갔다.
