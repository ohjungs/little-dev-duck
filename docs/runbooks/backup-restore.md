# 런북 — DB 백업·복구 (Phase 58 T1 V-010~V-012)

> 2026-07-29 작성. 무료 플랜에는 자동 백업이 없다(카탈로그 V-010 실측).
> 메신저에는 지우면 복구 수단이 없는 개인 대화가 쌓인다 — 이 문서가 그 대비 절차다.
> **복구해 본 적 없는 백업은 문서다**(Phase 40의 원칙) — 아래 리허설을 최소 1회 실행한다.

## 1. 백업 (수동 실행)

준비물: **DB Connection string(URI)** — Supabase 대시보드 → Project Settings → Database →
Connection string. 이 값은 시크릿이다. 파일·메모·커밋에 적지 않는다.

```bash
SUPABASE_DB_URL='postgresql://...' bash scripts/db-backup.sh
```

- 산출물: `backup/ldd-dump-YYYYMMDD-HHMMSS.sql` (스크립트가 빈 파일이면 실패로 처리한다)
- `backup/`은 `.gitignore`다 — **개인 대화가 저장소에 커밋되면 안 된다.**
- 보관 권고: 로컬 + 본인 소유의 사적 저장 공간(개인 클라우드 암호화 폴더 등).
  **GitHub·공유 드라이브 금지** — 대화 원문이 들어 있다.

### 스토리지(첨부 사진)는 이 덤프에 안 들어간다 — 정직한 한계

`pg_dump`는 DB만 담는다. **message-attachments 버킷의 사진 파일은 별도다.**
현재 무료 티어에서 버킷 일괄 덤프 도구가 없어, 사진까지 잃으면 안 되는 시점이 오면
(스토리지 사용량 계기판이 커질 때) 별도 스크립트를 추가한다. 지금은 이 한계를 안다는
사실 자체가 산출물이다.

## 2. 정기 실행 — 자동화의 한계를 정직하게

이 프로젝트는 무료 원칙이라 **서버 스케줄러가 없다.** "정기 백업"이라고 적어 두고 실제로
안 도는 것이 최악이므로, 선택지를 사실대로 적는다:

| 방법 | 현실성 |
|---|---|
| Windows 작업 스케줄러로 위 명령 주 1회 | **권장.** 기기가 켜져 있을 때만 돈다는 한계 명시 |
| GitHub Actions 정기 실행 | **비권장** — 개인 대화 덤프가 저장소 인프라 근처에 생긴다(계획 판단) |
| 수동(달력 알림) | 최소한의 대안 |

Windows 작업 스케줄러 등록 예(주 1회 일요일 21:00):

```powershell
schtasks /Create /TN "ldd-db-backup" /SC WEEKLY /D SUN /ST 21:00 `
  /TR "\"C:\Program Files\Git\bin\bash.exe\" -c 'SUPABASE_DB_URL=... bash c:/Users/User/Desktop/code/little-dev-duck/scripts/db-backup.sh'"
```

(URL을 명령에 박으면 작업 스케줄러에 시크릿이 남는다 — 사용자 환경변수로 두고 참조 권장.)

## 3. 복구 절차

**복구는 되돌리기 어렵다. 반드시 순서대로.**

1. **지금 상태를 먼저 백업한다**(위 1번) — 복구가 잘못되면 이것이 마지막 줄이다.
2. 복구 대상 파일을 고른다: `backup/ldd-dump-....sql`
3. 적용(psql 필요):
   ```bash
   psql "$SUPABASE_DB_URL" -f backup/ldd-dump-YYYYMMDD-HHMMSS.sql
   ```
   - 덤프는 `--no-owner --no-privileges`로 만들어져 소유자 충돌이 없다.
   - **기존 데이터와 병합되지 않는다** — 같은 키가 있으면 에러가 난다. 빈 프로젝트/스키마에
     복구하는 것이 원칙이다(부분 복구가 필요하면 파일에서 해당 COPY 구간만 추려 적용).
4. 복구 후 검증: 앱 로그인 → 방 목록·최근 메시지·할 일이 보이는지. `docs/Status.md`의
   실기 확인 절차(50번대) 일부를 재사용.
